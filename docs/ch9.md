# 第9章 运营自媒体

自媒体不是“写一篇就发”，而是一条链：选题、来源约束、写作、独立审稿、配图、平台适配、进草稿箱，最后才是人工发布。这一章介绍三个 Skill：一个管公众号从选题到草稿箱，一个把已有作品适配到小红书/抖音/视频号草稿箱，一个负责封面与图文卡片的视觉物料。自媒体本质上是一条明确的流水线，把选题、来源、写作、配图、平台适配分开处理，质量才有可能稳定，而不是每次看运气。

## 9.1 公众号从选题到草稿箱

### 简介

`publish-gzh` 覆盖公众号的完整生产链：选题、来源约束、中文写作、独立审稿、可选语义配图、确定性校验，最终进入草稿箱。设计重点是把“审稿”作为独立环节，而不是写作的附属。

独立审稿是什么意思？就是文章写完了，不直接发布，先让另一个人（或另一个 Skill）审一遍，看看有没有事实错误、有没有敏感词、有没有不通顺的地方。审稿通过了才能发布，这样可以避免很多低级错误。

```
# 写作前：来源清单与事实约束

## 选题

## 事实约束

1. MCP（Model Context Protocol）是 Anthropic 开放的标准协议，用于 AI Agent 与外部工具、数据源的连接。
2. Codex Skill 是 Codex 体系中的能力模块，决定 AI 如何使用连接好的工具。

4. MCP 的配置结构包括 stdio（command + args）和远程（url）两种方式。
5. 分工认知：MCP 把外部工具“连上”，Skill 决定“怎么用”。
```

## 9.2 跨平台草稿生成与上传

### 简介

`filler` 把已完成作品转成平台发布草稿：AI 写标题文案，CLI 校验素材，Playwright 自动上传到小红书、抖音、视频号的草稿箱。与 `publish-gzh` 互补：一个负责“从无到有写公众号”，一个负责“把已有内容适配到多平台草稿箱”。

什么叫“草稿箱”？就是文章先保存在平台的草稿箱里，不直接公开发布。你可以先看看草稿效果，修改一下，满意了再点击发布。这样可以避免直接发布出有问题的文章。

### 调用记录

我们先让模型演示跨平台适配：

```
我：把 11.1 的文章交给 `filler` 生成小红书版本，只到“草稿箱生成”为止，不实际发布；检查它是否为小红书做了标题长度、分段和话题标签适配，而不是原样搬运。
```

模型给出如下回复：

```
> filler 是一条跨平台发布草稿生成 Skill，底层用 Playwright 自动上传到小红书、抖音、视频号的草稿箱。与 publish-gzh 互补：publish-gzh 负责“从无到有写公众号”，filler 负责“把已有内容适配到多平台草稿箱”。

> 收到公众号文章后，filler 不会原样搬运。它会针对小红书平台特点做适配：标题压缩到小红书适宜长度（通常 20-30 字）、正文分段更短（适合手机屏幕阅读）、添加话题标签（#Codex #MCP #AI工具等）、添加表情符号增加可读性。
```

### 总结

- `filler` 把已完成作品转成平台发布草稿，不直接发布。
- 针对小红书平台特点做适配：标题压缩、正文分段更短、添加话题标签和表情符号。
- 草稿已生成到小红书草稿箱，未实际发布，用户可自行决定是否发布。

## 9.3 图文视觉物料的生成

### 简介

`guizang-social-card-skill` 从小红书图文组图到公众号封面对，把“找图”变成“按内容生成匹配的视觉物料”。对于不擅长设计的初学者，它降低了封面和组图的门槛；对于已经产出内容的读者，它是发布前最后一块拼图。

什么叫“视觉物料”？就是文章配图、封面、海报这些东西。不擅长设计的人很难做出好看的图，`guizang-social-card-skill` 就是帮这些人生成匹配文章内容的图片，不需要自己找图片或者学设计软件。
