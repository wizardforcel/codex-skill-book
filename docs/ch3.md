# 第3章 制作视频

视频是重交付物：一个三分钟的口播，光“把停顿和口误剪掉”就可能占掉整条制作链一半的时间。这一章介绍两个视频类 Skill，一个负责“粗剪 + 字幕”这条最耗时的链路，一个负责“配乐卡点成片”的风格化包装。你会看到，它们不是替代剪辑软件，而是把剪辑软件里那些“可被规则描述”的动作交给代码去做，让 AI 先给你一份能审阅的清单。

## 3.1 口播视频的自动粗剪与字幕

### 简介

`videocut-skills` 专为口播视频设计。当前可用的仓库是 `Agentchengfeng/chengfeng-videocut-skills`（Codex Plugin 形态），旧仓库 `ljiao0729-lang/videocut-skills` 里保留着最完整的“剪口播”技能文件。它的链路是：`提取音频 → 转录 → 识别口误/静音/重复句 → 生成审核网页 → 你逐条确认 → 执行剪辑`。

它最有价值的地方有三点：静音检测阈值可调；口误和重说靠语义理解识别而不是死规则；重复句按“相邻句开头≥5 字相同”删前保后。最终产出 `edited.mp4` 和 `edited.srt`，并且每一条删除建议都能在网页上单独审阅、单独决定。

### 调用记录

**我**：我想把手头一个 10 秒的口播素材跑一遍剪口播流程，怎么开始？

**Codex**：技能的名字是 `videocut:剪口播`，触发词是“剪口播、处理视频、识别口误”。它要求的输入是一个 `*.mp4`，输出目录是这样规划的：

```text
output/2026-11-03_视频名/
└── 剪口播/
    ├── 1_转录/
    │   ├── audio.mp3
    │   ├── volcengine_result.json
    │   └── subtitles_words.json
    ├── 2_分析/
    │   ├── readable.txt
    │   ├── auto_selected.json        # 预选删除清单
    │   ├── 静音分析.md
    │   ├── 语义分析.md
    │   └── 口误分析.md
    └── 3_审核/
        ├── review.html               # 审核网页
        └── video.mp4 → 源视频(符号链接)
```

**我**：那我先造一个测试素材。

**Codex**：本机有 ffmpeg，我直接生成一段 10 秒的测试口播视频（黑底 + 持续音），并提取音频：

```powershell
ffmpeg -y -f lavfi -i "sine=frequency=440:duration=10" -f lavfi -i "color=c=black:s=640x360:d=10" -c:v libx264 -preset ultrafast -c:a aac D:\ch3-test\test_koubo.mp4
# test_koubo.mp4   103507 字节

ffmpeg -y -i D:\ch3-test\test_koubo.mp4 -vn -acodec libmp3lame D:\ch3-test\1_audio.mp3
# 1_audio.mp3      80787  字节
```

这就是流程的第一步“提取音频”，`-vn` 表示去掉画面只留声音，转录和静音分析都基于这个 mp3。

**我**：转录呢？

**Codex**：技能把音频上传获取公网 URL 后，调用火山引擎大模型录音文件接口转录：

```text
POST https://openspeech.bytedance.com/api/v3/auc/bigmodel/submit
POST https://openspeech.bytedance.com/api/v3/auc/bigmodel/query
```

这一步需要火山引擎的密钥，本机没配置。真正跑到这里会停在 `volcengine_transcribe.sh` 返回的鉴权错误上；在有密钥的环境里，它会写出 `volcengine_result.json`，再生成字级别字幕 `subtitles_words.json`。

**我**：那“识别了口误”到底怎么识别？

**Codex**：转录之后先按静音切句（静音≥0.5 秒当分隔），再按下面的规则表比对：

| # | 类型 | 判断方法 | 删除范围 |
|---|------|----------|----------|
| 1 | 重复句 | 相邻句子开头≥5字相同 | 较短的整句 |
| 2 | 隔一句重复 | 中间是残句时，比对前后句 | 前句+残句 |
| 3 | 残句 | 话说一半+静音 | 整个残句 |
| 4 | 句内重复 | A+中间+A 模式 | 前面部分 |
| 5 | 卡顿词 | 那个那个、就是就是 | 前面部分 |
| 6 | 重说纠正 | 部分重复/否定纠正 | 前面部分 |
| 7 | 语气词 | 嗯、啊、那个 | 标记但不自动删 |

技能里 `用户习惯/4-重复句检测.md` 写的判断逻辑是这样的：

```javascript
// 相邻句子比对
if (curr.text.slice(0, 5) === next.text.slice(0, 5)) {
  const shorter = curr.text.length <= next.text.length ? curr : next;
  markAsError(shorter);  // 删除整句，不只是重复部分
}
```

注意核心原则是“先分句，再比对；删整句，不只删几个字”。

**我**：静音又是怎么处理的？

**Codex**：脚本 `generate_auto_selected.js` 会按听感原则自动标记：同一句内 ≥0.18 秒停顿默认删；≤0.8 秒的句间停保留；0.8–1.2 秒只写进分析报告不自动删；≥1.2 秒的连续静音块整段预选删除。它输出 `auto_selected.json` 和 `静音分析.md`；接着语义脚本再追加残句、重说、孤立卡顿词候选中，写 `语义分析.md`。

**我**：然后我怎么确认这些删除？

**Codex**：技能生成 `review.html` 审核网页并启动本地服务器，把每条预选删除列成可逐条勾选的项目，旁边还挂着 `video.mp4` 预览。你只需要点击确认，最后点「执行剪辑」。也可以只确认其中前 3 条，让技能先剪这 3 条——这就是“可逐条审阅的删除清单”的意义：机器建议，人拍板。

### 总结

- 剪口播的链路是固定的：提取音频 → 转录 → 分句 → 按规则表标口误/静音 → 生成审核网页 → 确认后执行剪辑。
- 口误识别有 7 类规则，核心原则是“先分句再比对、删整句不删碎片”。
- 静音处理按听感阈值分层：句中 0.18s、句间 ≤0.8s、0.8–1.2s 只报告、≥1.2s 整段预删。
- 转录环节依赖火山引擎接口和密钥；没有密钥时会如实停在鉴权错误，不会伪造转录结果。
- 删除建议先进 `auto_selected.json`，再经 `review.html` 人工逐条确认，机器不替你做最终决定。

## 3.2 卡点转场与产品宣传片

### 简介

`match-cut` 是一个默认做 20 秒产品宣传片的 Skill，风格是“匹配剪辑接力”：同一个形状或动作持续移动，每到一次剪辑就切进一个新世界，严格卡在节拍网格上，最后停在产品英雄镜头和结尾卡。它把整件事组织成四个阶段：`方案 → 静帧与动态预演 → 成片 → 后期交付`，并强制你在每个检查点批准，而不是让它一口气烧完预算。

它有两个硬依赖：音频、音乐、旁白、拟音和交付都通过 Renoise MCP；静帧可以用 Codex 自带的 `image_gen`。所以“装了 Skill”和“能出片”是两回事，后者还要求你先接好 MCP。

### 调用记录

**我**：我想做一个“桌面咖啡杯”20 秒匹配剪辑短片。

**Codex**：先做阶段 0 检查。技能要求每个主机先连接 Renoise MCP，Codex 的命令是：

```powershell
codex mcp add renoise --url https://renoise.ai/api/public/mcp
codex mcp login renoise
```

本机当前 `codex mcp list` 只有 `chrome-devtools` 和 `echo`，没有 `renoise`，所以脚本真正开工前会先停下来等这个连接。技能明确写了“绝不索取 API Key”：登录签名是这个 Skill 自己的 MCP 服务在浏览器里完成的。

**我**：那在没连 Renoise 之前，能先出方案吗？

**Codex**：可以，方案阶段不消耗额度。它先选择切入角度，并要求写出“为什么这个角度合适”，不能混搭两种角度。对咖啡杯，我按技能里的角度对照表选“一个品质作为隐喻”：杯子传热快、拿起来就有温度，所以每个世界都表达“抵达你手心的那一刻”。

**我**：方案里到底要有什么？

**Codex**：20 秒默认是 150 BPM、25 fps，所以一拍正好 10 帧，每个剪辑都落在帧上。默认结构是：

```text
开场      8 拍    先教观众规则，用的必须是产品自己的形状和运动
接力      18 拍   3-4 组：世界里的动作 2 拍 → 产品上同一动作 2-3 拍
呼吸      4 拍    音乐变薄，主题词逐词出现
队列      9 拍    同一个机位，一个世界一拍，最后一拍拎起产品
英雄镜头  7 拍    由拎起动作接力到达，不是黑屏硬切
结尾卡    4 拍    logo + 名字，在音乐的最后一击中硬切
```

技能要求核心产物是“剪接表”：每一行是一个镜头，写清楚机位、世界、光照、动作的具体握法和方向、在哪一帧切、它和上一镜怎么匹配。比如咖啡杯的开场镜头可以写成：

```text
# | 帧/拍 | 画面 | 动作 | 在哪切 | 怎么匹配 | 含义
1 | 12拍 | 桌上俯拍 | 手掌从画面右下进入，虎口托住杯身 | 杯缘碰到画面中心线 | 圆/垂直轴线居中 | 这杯咖啡是主角
2 | 10拍 | 水龙头下 | 手指试水温 | 水珠落点同杯缘位置 | 圆点同位置 | 温度来自源头
```

技能有一条硬检查：每个动作都要能用物理方式写出来——谁的手、用什么握法、从哪个状态到哪个状态；写不出来的镜头就重设计。它还会检查镜头方向、速度、中心点（±3% 以内）这些数字，而不是“看着像”。

**我**：方案出来后怎么继续？

**Codex**：保存 `plan.md` 和第一版 `montage.json`，然后进入检查点①：你批准方案、模型、工作模式和这一阶段预算上限。如果没有提供产品的官方图和 logo，方案会继续，但在检查点消息里列成“阶段 2 之前必须提供”。批准之后才去做静帧、音乐候选和动态预演，最后出成片。由于本机还没有 Renoise 连接，本次验证停在这里是技能的正确行为，不是故障。

### 总结

- match-cut 默认 20 秒，150 BPM、25 fps，一拍 10 帧，剪辑必须卡帧。
- 方案阶段先选一种角度并解释理由，禁止混搭两种角度。
- 剪接表是方案核心，每个镜头的动作要能写成物理可执行的动作（谁、什么握法、从哪到哪）。
- 每个剪辑要过 8 项检查，包括方向、速度、中心位置和动作在切点是否连续。
- Renoise MCP 是硬前置，未连接时技能停在方案/设置阶段，不会假装出片。

## 3.3 从粗剪到包装的衔接

### 简介

粗剪 Skill（3.1）负责清洗素材：去口误、静音、废句，把人说的话整理干净。卡点 Skill（3.2）负责包装：切角度、配乐、卡节奏、出英雄镜头。它们是视频生产链上两道不同的工序。本节要验证衔接的关键问题：**粗剪的产物能不能直接被卡点 Skill 接受为输入？** 答案需要看技能自己的输入契约，而不是想当然。

### 调用记录

**我**：我把 3.1 剪出来的 `edited.mp4` 直接交给 3.2，让它做 20 秒卡点版本，行吗？

**Codex**：查了 match-cut 的 `SKILL.md` 和 `references/generation.md`，它的输入契约是这样的：

```text
- 产品事实、官方产品图（每个状态一张）和 logo。
- 官方图通过 Renoise 的 upload_files 上传，作为生成静帧的 reference_image。
- 视频、音乐、旁白、拟音由 Renoise 生成，不是由已有视频剪辑而来。
```

里面没有任何“导入用户视频作为剪辑源”的步骤。也就是说，match-cut 不是剪你的实拍素材，而是照着方案生成一支新片；直接用 `edited.mp4` 喂它，不在它的输入契约里。

**我**：那这道衔接到底怎么走？

**Codex**：不是传视频，而是传“资产 + 事实”。可行的做法有三种，第一条本机可以立刻跑通：

1. **抽关键帧当参考图**：从粗剪成片里按间隔抽帧，转成产品参考图，再进 match-cut 的静帧流程。本机实测：

```powershell
ffmpeg -y -i D:\ch3-test\test_koubo.mp4 -vf "fps=1/3" D:\ch3-test\frames\frame_%02d.png
# frame=3  time=00:00:09.00  speed=295x
# 生成 frame_01.png / frame_02.png / frame_03.png
```

2. **把粗剪当成实拍参考**：在 match-cut 的方案阶段，用 `edited.mp4` 里确立的产品形象、光照、机位来写剪接表，让生成的静帧在视觉上对得上它。
3. **最终在剪辑软件里合成**：粗剪负责“人说话的段落”，卡点成片负责“产品节奏段落”，最后你在时间线上把两段拼起来。

**我**：那这两节合成一条链，关键是什么？

**Codex**：共享的不是视频文件，而是同一个“产品资产”：产品图、logo、事实与风格参考。粗剪决定了哪些内容能留，match-cut 决定了镜头怎么被看见；衔接的对接点是抽帧、参考图和一份被两边都认可的事实清单，而不是把一个 mp4 塞进另一个的输入。

### 总结

- 两个 Skill 覆盖不同工序：3.1 清洗“人说的话”，3.2 包装“产品和节奏”。
- 不能假设技能之间天然可串联：先查输入契约，match-cut 不接收已有成片作为剪辑源。
- 可行的衔接是资产对接：从粗剪抽关键帧、把粗剪当实拍参考、最终在剪辑软件合成。
- 用 `ffmpeg -vf fps=1/3` 抽帧是把成片转成参考图的最小动作。
