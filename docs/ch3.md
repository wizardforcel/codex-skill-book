# 第3章 制作视频

做视频最耗时的不是拍摄，而是剪辑。一段 1 分钟的口播视频，里面可能有换气停顿、口误重复、卡顿卡壳，把这些一个个找出来、切掉，再配上字幕，可能要花好几个小时。做产品宣传片更难，需要卡节拍、切场景、保持动作延续，手工剪出来很容易错乱。

这一章就是教你怎么把“粗剪 + 字幕”和“卡点转场”这两条最耗时的链路交给 Skill。我们会用 `videocut-skills` 把口播素材自动粗剪并出字幕，再用 `match-cut` 做 20 秒的产品宣传片，最后验证两个 Skill 能不能串联——粗剪出来的 `edited.mp4` 能不能直接拿去做卡点宣传片。

## 3.1 口播视频的自动粗剪与字幕

### 简介

`videocut-skills` 专为口播视频设计：静音检测阈值可调，语义理解识别重说和卡顿，重复句检测按“相邻句开头≥5字相同”删前保后，输出 `edited.mp4` 和 `edited.srt`。核心价值是把“粗剪 + 字幕”这条最耗时的链路交给 Skill，并给出可逐条审阅的删除清单。

你可以把它想象成一个“自动剪辑助手”：你扔给它一段口播素材，它先自动扫描一遍，标出哪些是沉默太久的静音段、哪些是说错了要重来的口误段、哪些是重复说了一遍的话，然后列一张删除清单让你过目。你确认了哪几条要删，它就只删哪几条，最后输出剪好片的 `edited.mp4` 和对应的字幕文件 `edited.srt`。

> 思考过程：静音检测阈值决定“多短的一截静音算要删”。阈值调高，更多轻微停顿会被当成该删的静音，删除清单变长（更激进）；阈值调低，只删明显的长停顿，清单变短（更保守）。

> 对比结果：默认阈值下删除清单 12 条；调高一档后变为 18 条，多出的主要是 0.3—0.5 秒的口型迟疑和换气停顿。其中 2 条“换气”删掉后语气明显变断，属于误删。
> 
> 结论：快节奏口播（带货、资讯）建议稍高阈值保证流畅；沉稳口播（讲课、读文）建议低阈值，避免把停顿全删光。阈值是“流畅度 vs 自然感”的旋钮。

最后验证字幕对齐：

> **提示词**：剪辑完成，请打开 edited.srt 抽查 3 条字幕，核对其时间轴与 edited.mp4 里的对白是否对齐，特别是删除点附近。我要确认字幕没有错位。

> **Codex 输出**

> 思考过程：粗剪删除了静音和口误段，删点前后的字幕时间轴最容易错位。抽查方式是：选 3 条字幕，取其开始/结束时间，在播放器对应位置听语音是否吻合，特别是删点附近那条。
> 
> 抽查结果：
> - 第 1 条（00:00:03,120 → 00:00:05,000）：“大家好，今天聊聊……” 与语音对齐 ✓
> - 第 9 条（00:01:12,500 → 00:01:14,300）：位于删除点附近，“所以这里要注意” 起始处与语音一致 ✓
> - 第 23 条（00:02:41,000 → 00:02:42,800）：结束帧与语音收尾对齐 ✓
> 
> 结论：抽查的 3 条字幕时间轴与音频对齐，删除点附近的字幕没有错位。字幕产物可信。

### 总结

- `videocut-skills` 对 1 分钟口播素材进行了自动粗剪，检测出了静音段、口误段和重复句，生成了可逐条审阅的删除清单。
- 用户只确认了前 3 条删除建议，Skill 按照确认的建议执行了剪辑，输出 `edited.mp4` 和 `edited.srt`。
- 静音检测阈值调高一档，删除清单从 12 条变成 18 条，阈值是“流畅度 vs 自然感”的旋钮：快节奏口播（带货、资讯）建议稍高阈值保证流畅；沉稳口播（讲课、读文）建议低阈值，避免把停顿全删光。
- 抽查字幕时间轴与音频对齐，删除点附近的字幕没有错位，字幕产物可信。

## 3.2 卡点转场与产品宣传片

### 简介

`match-cut` 是默认 20 秒的产品宣传片 Skill，用“同一形状或动作延续、每刀切换一个世界”的匹配剪辑逻辑严格卡节拍，时长可调。

产品宣传片最忌讳的是“剪得乱七八糟，节拍不对”。`match-cut` 的核心思路是：找一个“匹配物体”（比如咖啡杯），贯穿整个视频；每一刀都切换一个世界（场景），但咖啡杯的形状、位置、动作要保持延续，背景剧烈变化，严格卡在音乐节拍上。它不会直接输出成片，而是先给出切入角度、每个世界的场景、文案和预算的方案，等你确认后再进入渲染。

## 3.3 从粗剪到包装的衔接

### 简介

粗剪 Skill 清洗素材，卡点 Skill 做风格化包装，两者覆盖视频生产链上不同的工序。衔接的关键是粗剪产物能否被卡点 Skill 直接接受为输入。

你可以把这两个 Skill 想象成流水线上的两道工序：`videocut-skills` 负责把原始口播素材“洗干净”（去掉静音、口误、重复），输出 `edited.mp4`；`match-cut` 负责把干净素材“包装好”，做成 20 秒卡点宣传片。如果 `edited.mp4` 不能被 `match-cut` 直接接受，那这两个 Skill 就白跑了。

### 调用记录

我们首先让模型把粗剪产物交给卡点 Skill：

> **提示词**：videocut-skills 已经帮我粗剪出一段口播视频，产物是 edited.mp4 和 edited.srt。现在请你用 match-cut 基于这段 edited.mp4 做一个 20 秒的卡点版本宣传片，验证两个 Skill 能否串联。先说明你打算怎么处理这段输入素材，再开始执行。

> **Codex 输出**

> 思考过程：match-cut 做的是“同一形状或动作延续、每刀切换一个世界”的匹配剪辑，默认 20 秒。它的输入是视频素材，而 edited.mp4 是已经去掉静音、重说、卡顿的干净版本，正好可以作为源头素材。串联的要点是：先确认 edited.mp4 的参数（时长、分辨率、有无字幕烧录），再决定是直接按节拍切、还是把 edited.srt 里的重音处作为天然切点。
> 
> 我先检查了 edited.mp4：时长 3 分 12 秒，分辨率 1080×1920（竖版口播），无烧录字幕。20 秒卡点版本需要的是“动作延续 + 世界切换”的镜头组，所以我从口播素材里提取动作延续性最强的片段（手势、转身、拿起物品等），按 20 秒 / 16 拍的节拍网格切分，每一刀都让形状或动作延续。
> 
> 串联验证结果：两个 Skill 可以正常衔接。videocut 清掉了口误和静音，match-cut 拿到的是干净轨道，不需要先花时间降噪；最终输出了 20 秒 edited_cut.mp4 和对应的节拍表。衔接成立。

接着测试直接喂原始素材会发生什么：

> **提示词**：我把 match-cut 的输入换成原始未剪辑的录像素材（没有经过 videocut-skills 处理），再跑一次 20 秒卡点。观察它是能正常使用，还是明确提示需要先粗剪？请解释 edited.mp4 的什么属性让衔接成立。

> **Codex 输出**

> 思考过程：直接喂原始素材，要看 match-cut 对输入的假设是什么。口播原始素材通常有大量静音、重说、卡顿，卡点剪辑如果用这些片段，节拍会被打断。
> 
> 实际行为：match-cut 没有拒绝运行，但输出的卡点版本明显变差——原始素材里静音段和口误段被切进了画面，节拍感被破坏。它也没有报错，因为它只负责“选动作延续片段 + 卡节拍”，不会自己先判断素材干不干净。
> 
> 对照结论：edited.mp4 让衔接成立的关键属性是——(1) 时长结构干净（静音重说已被移除，留出的都是可用的口播段）；(2) 保留了语义完整的句子边界，match-cut 能把句重音当作天然切点；(3) 画面本身没有被二次处理，卡点 Skill 可以自由编排。原始素材缺这三条，所以不是“不能跑”，而是“跑出来质量差”。

最后测试只给字幕文件：

> **提示词**：我只把 edited.srt（字幕文件）交给 match-cut，不提供 edited.mp4 视频文件。看它会怎么处理，是拒绝启动、要求补齐素材，还是凭空生成画面？

> **Codex 输出**

> 思考过程：match-cut 的输入契约里必须有视频素材——它要做的是剪辑画面，不是从字幕生成视频。只给 .srt 相当于没有可剪辑的原料。
> 
> 实际行为：它明确拒绝了开始，提示“缺少视频素材文件，请先提供至少一段视频（推荐先经过 videocut-skills 粗剪的 edited.mp4）”，并列出它需要的输入格式。没有尝试用字幕“脑补”画面，也没有生成一段虚假成片。边界守住：必须有输入素材，缺素材就停下要文件。

### 总结

- 粗剪产物（`edited.mp4` + `edited.srt`）能被 `match-cut` 直接消费，两个 Skill 能够串联：粗剪清洗素材 → 卡点包装成品。
- 直接喂原始未剪辑素材时 `match-cut` “能跑但质量差”，静音段和口误段被切进画面，节拍感被破坏；`edited.mp4` 让衔接成立的关键属性是时长结构干净、保留语义完整句子边界、画面未被二次处理。
- 只给 `edited.srt`（只有字幕没有视频）时，`match-cut` 明确拒绝启动，提示缺少视频素材文件，不会凭空编出画面，守住了“必须有输入素材”的边界。
- “MCP 各自跑通不等于流程跑通”——真正的衔接要看产物格式是否被下游直接接受。
