## data-analysis-skills

### 第 7.1 节 —— 表格数据的 EDA 与建模：Titanic
- **实操一 · 验证 EDA 纪律**：让 Codex 用 `safe-kaggle-mcp` 拉取 Titanic 训练集，再用 `data-analysis-skills` 做“生存率影响因素”EDA。要求先给出缺失率表和目标变量分布，再重点检查 `Sex`、`Pclass`、`Age` 与 `Survived` 的关系，并明确标注哪些结论是描述性统计、哪些只是相关而非因果。检查 HTML 报告每张图是否配有解读，以及是否声明了样本量和缺失处理方式。
- **实操二 · 验证拉取与本地落地**：先用 `safe-kaggle-mcp` 拉取 Titanic 数据，查看本地生成的文件路径与格式；再让 MCP 返回 pandas digest（schema、缺失率、分布摘要），确认拿到的是结构化摘要而不是几百行原始数据灌进对话框。
- **实操三 · 验证小样本不下结论**：让 Codex 只基于一个很小的子集（如仅 `Pclass==3` 且标注不做因果推断）回答“什么因素影响生存率”，检查它是否明确标注样本范围与“相关≠因果”，而不是用大样本结论冒充观察结论。

### 第 7.2 节 —— 不平衡表格数据的审查与基线：Credit Card Fraud
- **实操一 · 验证不平衡指标**：让 Codex 先输出正类占比和特征缺失/量纲概况，再训练一个逻辑回归基线和一个带 `class_weight='balanced'` 的基线，同时报告 PR-AUC、precision、recall 和混淆矩阵，并明确回答：“如果只看 accuracy，这个模型会给人什么错觉？”检查报告是否指出 accuracy 在不平衡数据上的误导性，而不是给出一个 99.8% 的数字就结束。
- **实操二 · 验证业务代价翻译**：拿到混淆矩阵后，让 Skill 把它翻译成业务语言：“这个模型在 1000 笔交易里会抓出几笔欺诈、会误伤几笔正常交易”，并说明在“宁可多拦不可漏”和“宁可少拦不可扰”两种场景下应该往哪个方向调阈值。
- **实操三 · 验证策略可复现**：让 Skill 把训练过程用固定随机种子重跑一遍，确认两次产出同一份 PR-AUC 与混淆矩阵，并检查报告里是否写明了重采样/类别权重的具体策略，而不是只给一个模糊的“处理过不平衡”。

  - **实操一 · 验证跨段一致**：Chrome MCP 读取 `example.com` 的 `<h1>`，Windows-MCP 写入桌面 `example-h1.txt`，Skill 校验文件内容与页面标题是否一致；不一致时输出差异。
  - **实操二 · 验证不一致检测**：故意让页面标题与文件内容不同（例如手工修改文件内容），重跑校验，确认 Skill 能够输出“不一致”及具体差异，而不是假装校验通过。
  - **实操三 · 验证断链处理**：先不启动 Chrome MCP（或让浏览器段超时），只跑编排，观察 Skill 是否在浏览器段失败时停下来报告原因，而不是跳过浏览器段直接写一个空文件到桌面。
- **12.7 收束：从选股到研报的完整链路**：无（概念收束）。小实操：
  - **实操一 · 验证链路衔接**：任选两个 Skill 对照输出，例如 12.2 重建的因子公式是否在 12.3 中被检查未来函数和可运行性，12.4 的排雷问题卡是否在 12.6 中被引用为风险披露；再用 12.1 排名靠前的一只股票，让 12.3 生成一个“动量”相关候选因子，检查该股票在该因子上的暴露方向是否与 12.1 的动量评分方向一致。若链路断掉，先补交接而不是继续装更多 Skill。
  - **实操二 · 验证断链定位**：人为制造一处断链（如把 12.2 的复现产物放在别的目录），重跑 12.3，观察你是否能凭“找不到输入”的报错定位断点，并把交接说明写进备忘录，而不是跳过这步直接出结论。
  - **实操三 · 验证全程可追溯**：把本章产出（选股排名、复现包、因子 JSON、问题卡、组合建议、研报）列成一张“产物 → 来自哪节 → 谁能复现验证”的对照表，检查每一行都能填满，填不满的就是下一步要补的交接。
- **13.6 边界收束：可复现 + 不越界**：本章全部（参照 tarot-skill 的安全边界 + 各排盘 Skill 的计算约束）。小实操：
  - **实操一 · 验证双条件自查**：任选一个跑通的命理 Skill，检查输出是否同时满足：(a) 包含排盘/起卦的事实字段（四柱 / 卦象 / 排盘 JSON / 塔罗 seed）；(b) 包含显式边界声明或高风险话题处理规则。只有 (a) 没有 (b) 是“算得准但不敢用”；只有 (b) 没有 (a) 是“话说得漂亮但不可验证”。
  - **实操二 · 验证跨 Skill 对照**：固定一个问题，分别用本章两个不同 Skill 各跑一次，比较两者的“事实字段”和“边界声明”是否都齐全，列出缺 (a) 或少 (b) 的具体位置，检验全章不是只在一两个 Skill 上达标。
  - **实操三 · 验证可重复交付**：选一个 Skill 用固定 seed/输入跑两次，把两次的字段输出存成两个文件做 diff，确认完全一致，然后把“事实字段 + 边界声明”两条检查做成自己的核对清单，用于以后评估任何命理类 Skill。
