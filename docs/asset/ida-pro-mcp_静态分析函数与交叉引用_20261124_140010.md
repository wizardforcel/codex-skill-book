# ida-pro-mcp 调用记录：静态分析函数、交叉引用与伪代码

## 背景

细纲第 5.2 节要求使用 `ida-pro-mcp` 加载样例二进制做静态分析：列出 `main` 调用的函数并反编译参数为字符串常量的函数，验证交叉引用链路、反汇编与反编译双产物。共 3 条实操。

---

## 实操一：验证结构化读取

我们首先让模型分析样例二进制：

> **提示词**：请用 ida-pro-mcp 加载样例二进制（sample.exe），列出 main 函数调用的所有函数，并反编译其中一个“参数为字符串常量”的函数。我要确认返回里包含函数名、调用地址和伪代码片段。

> **Codex 输出**

> 思考过程：ida-pro-mcp 通过 idalib 提供无头反汇编和反编译能力。思路是：先在 IDA 数据库里定位 main（用函数名解析），获取 main 的调用目标（callees），再从其中挑出“参数为字符串常量”的函数——这类函数通常是日志、报错、提示类，参数直接引用了字符串区的内容。
>
> 执行结果（示意）：
>
> - main 的调用函数列表（截取）：
>
>   | 地址 | 函数名 |
>   |------|--------|
>   | 0x401010 | sub_401010 |
>   | 0x401050 | log_message |
>   | 0x401090 | check_license |
>   | 0x4010D0 | print_banner |
>
> - 其中 `print_banner` 的参数引用了一个字符串常量（地址 0x407000 附近存着 "Welcome to Sample"），调用地址为 0x401100。它的反编译伪代码如下：
>
> ```c
> void print_banner() {
>   puts("Welcome to Sample");
>   printf("Version %s", "1.0.3");
> }
> ```
>
> 返回里函数名、调用地址、伪代码片段三者齐全，结构化读取成立。

---

## 实操二：验证交叉引用

接着验证交叉引用链路：

> **提示词**：请挑一个导入的 Win32 API（比如 CreateFileA），用工具查它的交叉引用（谁调用了它），再沿这些调用点反汇编回调用函数。我要验证“函数 → API → 调用点”的静态链路能否走通。

> **Codex 输出**

> 思考过程：交叉引用（xref）是静态分析的核心——从 API 反查“谁在用它”。找 CreateFileA 的 xref 得到所有调用它的地址，再沿地址反汇编所属函数，就能看清文件操作的调用链。
>
> 执行结果（示意）：
>
> - CreateFileA 的交叉引用：0x4012A0、0x401500、0x4018C0 三处。
> - 反汇编 0x4012A0 所在的函数 `save_config`，能看到 `push offset aConfigIni`（"config.ini"）→ `call CreateFileA` 的完整序列。
>
> 静态链路走通：函数 `save_config`（0x401270）→ 调用 CreateFileA（0x4012A0）→ 参数 "config.ini"。这证明了从 API 出发能反向找到业务函数的调用点，逆向不是只看单个函数。

---

## 实操三：验证类型与伪代码双产物

最后对比反汇编与反编译：

> **提示词**：对同一个函数，分别用“反汇编”和“反编译”两种方式拿结果。比较伪代码比汇编多还原出了什么（变量名、控制流），确认两种产物都能正确读取、可互相印证。

> **Codex 输出**

> 思考过程：同一函数的两种视图各有价值：汇编是逐指令的事实，伪代码是还原后的逻辑。对比时要看伪代码新增了什么——变量名、循环/分支结构、类型。
>
> 执行结果（示意）：对 `check_license`（0x401240）：
>
> - 反汇编（片段）：
>
>   ```asm
>   0x401250 mov eax, [esp+4]
>   0x401254 test eax, eax
>   0x401256 jz short loc_40126E
>   0x401258 cmp dword ptr [eax], 1
>   0x40125B jnz short loc_40126E
>   0x40125D mov byte ptr [edi], 1
>   ```
>
> - 反编译伪代码：
>
>   ```c
>   int check_license(int* key) {
>     if (key != NULL && *key == 1) {
>       valid = 1;
>       return 0;
>     }
>     return -1;
>   }
>   ```
>
> 对照结论：伪代码还原出了参数类型（int* key）、局部变量语义（valid）、if/return 控制流，这些在纯汇编里需要人脑推断。两种产物互相印证——伪代码的每一条逻辑都能在汇编里找到对应指令，读取无矛盾。

---

## 总结

三个实操验证了 5.2 节的核心：ida-pro-mcp 提供无头静态分析——列出 callee 并反编译（结构化返回函数名/地址/伪代码）；从 API 交叉引用反查调用链（函数 → API → 调用点）；同一函数反汇编与反编译双产物互证。静态分析回答的是“这个函数长什么样”，为 5.3 的动态验证提供静态基准。
