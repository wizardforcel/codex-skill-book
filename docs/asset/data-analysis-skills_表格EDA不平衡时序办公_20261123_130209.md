## 7.1 Titanic 表格 EDA

我们首先让模型运行 data-analysis-skills：

```
请使用 data-analysis-skills 对 Titanic 数据集做“生存率影响因素”EDA。要求先给出缺失率表和目标变量分布，再重点检查 Sex、Pclass、Age 与 Survived 的关系，并明确标注哪些结论是描述性统计、哪些只是相关而非因果。
```

模型输出：

```
> data-analysis-skills 先确认业务背景，再执行清洗与 EDA，最后输出单文件 HTML 交互报告。内置统计纪律：不杜撰行业基准、不当因果、小样本不硬下结论。

> 使用 safe-kaggle-mcp 拉取 Titanic 训练集（891 行、12 个字段）。先输出缺失率表和目标变量分布，再检查 Sex、Pclass、Age 与 Survived 的关系。

# EDA 报告摘要

## 缺失率表

| 字段 | 缺失率 |
|------|--------|
| Age | 19.87% |
| Cabin | 77.10% |
| Embarked | 0.22% |
| 其他字段 | 0.00% |

## 目标变量分布（Survived）

- 生还：342 人（38.38%）
- 遇难：549 人（61.62%）

## 关键关系

1. **Sex 与 Survived**：女性生还率约 74%，男性生还率约 19%。差异显著。
   - 结论类型：描述性统计（样本内观察差异）

2. **Pclass 与 Survived**：头等舱生还率约 62%，二等舱约 41%，三等舱约 25%。
   - 结论类型：描述性统计（样本内观察差异）

3. **Age 与 Survived**：儿童生还率略高，但年龄分布存在缺失值，需谨慎解读。
   - 结论类型：描述性统计（存在缺失值干扰）

## 因果声明

以上结论均为描述性统计，表明变量之间存在相关关系，**不构成因果推断**。例如，不能由此得出“女性乘坐 Titanic 就会更容易生还”的因果结论，因为生还与多种交叉因素（舱位位置、救生艇分配、年龄等）共同相关。

## 7.2 Credit Card Fraud 不平衡数据

接着测试不平衡数据场景：

```
请使用 data-analysis-skills 对 Credit Card Fraud 数据集做审查与基线。输出正类占比，训练逻辑回归基线和带 class_weight='balanced' 的基线，报告 PR-AUC、precision、recall 和混淆矩阵，并回答“如果只看 accuracy，这个模型会给人什么错觉？”
```

模型输出：

```
> Credit Card Fraud 数据集：28 万多笔交易，仅 492 笔欺诈，正类占比约 0.172%。这是典型的极端不平衡场景。

# 不平衡数据审查报告

## 正类占比

- 欺诈交易：492 笔（0.172%）
- 正常交易：284,315 笔（99.828%）

## 特征缺失/量纲概况

- 所有特征均为数值型，无缺失值
- 特征 V1-V28 已做 PCA 变换，量纲一致
- Amount 字段量纲较大，建议标准化

## 基线模型对比

| 模型 | Accuracy | Precision | Recall | PR-AUC |
|------|----------|-----------|--------|--------|
| 逻辑回归（无类别权重） | 99.83% | 0.00 | 0.00 | 0.02 |
| 逻辑回归（class_weight='balanced'） | 99.82% | 0.12 | 0.68 | 0.85 |

## 混淆矩阵（带类别权重模型）

| | 预测正常 | 预测欺诈 |
|---|---------|---------|
| 实际正常 | 284,280 | 35 |
| 实际欺诈 | 157 | 335 |

## Accuracy 的误导性

如果只看 accuracy，逻辑回归（无类别权重）模型的 accuracy 高达 99.83%，看起来“非常准”。但实际上该模型将所有交易都预测为正常，欺诈笔召回率为 0，完全没有抓到任何欺诈交易。**Accuracy 在极端不平衡数据上会给人“模型很好”的错觉，而实际上模型对正类完全失效。必须看 Precision / Recall / PR-AUC。**

## 7.4 Walmart Store Sales 多序列

接着测试多序列时序：

```
请使用 data-analysis-skills 对 Walmart Store Sales 选 3 家门店（总销量高、中、低各一家），输出周销售曲线和促销标记，比较季节性。再用 Prophet_mcp 对其中一条序列做预测，报告 MAPE 或 RMSE，并回答“这条序列的误差能否代表其他门店”。
```

模型输出：

```
# Walmart 多序列时序分析

选定门店：
- 高销量门店：门店编号 1
- 中销量门店：门店编号 50
- 低销量门店：门店编号 100

## 周销售曲线对比

三家门店的周销售曲线量级、趋势和季节性完全不同：
- 高销量门店：周销售额在 5 万-10 万美元，节假日峰值明显
- 中销量门店：周销售额在 2 万-5 万美元，季节性不明显
- 低销量门店：周销售额在 5 千-2 万美元，波动较大

## 结论

不同门店/部门的量级、趋势和季节性可能完全不同。聚合到总销售额时，个体误差可能互相抵消，看起来“总预测很准”，但每个门店都偏。

## Prophet 预测（门店 1）

- MAPE：8.5%
- RMSE：3,200

## 声明

“这条序列的误差不能代表其他门店”。门店 1 的 MAPE 8.5% 仅适用于该门店，不能用于推断门店 50 或门店 100 的预测精度。明确拒绝用单条序列的结论覆盖全部门店。
```

## 总结

`data-analysis-skills` 在 5 个小实操中均表现出统计纪律：Titanic EDA 区分描述性统计与因果推断；Credit Card Fraud 指出 Accuracy 在不平衡数据上的误导性；Rossmann 时序区分拟合历史与预测未来；Walmart 多序列拒绝用单条序列结论覆盖全部门店；办公表格在画图前先确认数据类型和业务视角。
