# 第7章 数据分析：从 Kaggle 表格到时序

数据分析最容易犯的错不是“算错了”，而是“拿错了结论”。比如看到 99.8% 的 accuracy 就觉得模型很好，结果模型把所有交易都判成正常，一笔欺诈都没抓到；比如只看全历史拟合线漂亮，结果预测未来完全不准；比如只看一家门店的销售额，就觉得所有门店都一样。

这一章就是教你怎么带着“统计纪律”做数据分析：不杜撰行业基准、不当因果、小样本不硬下结论、不把 accuracy 当结论、不把单条序列的误差覆盖全部门店。我们会用 `data-analysis-skills` 做表格 EDA、不平衡数据基线、时序趋势与回测、多序列时序；用 `skill-creator` 把这些重复出现的动作固化成一个可复用的分析 SOP。

## 7.1 表格数据的 EDA 与建模：Titanic

### 简介

Titanic 是 Kaggle 最经典的表格二分类数据集，891 行、12 个字段，天然带有缺失值、类别不平衡和需要特征工程的结构。`data-analysis-skills` 先确认业务背景，再执行清洗与 EDA，最后输出单文件 HTML 交互报告，统计纪律内置——不杜撰行业基准、相关不当因果、小样本不硬下结论。`safe-kaggle-mcp` 负责把数据集直接拉到本地，并提供紧凑的 pandas digest EDA 工具，返回 schema、缺失率、分布摘要这类结构化结果，而不是把原始行灌进上下文。

你可以把它想象成体检：医生不会先给你开一大堆药，而是先量血压、查血化验、看缺失值（你有没有漏掉的指标），再根据结果分析。`data-analysis-skills` 也是先查缺失率表和目标变量分布，再看关键字段与生存率的关系，最后明确标注哪些结论是描述性统计、哪些只是相关而非因果。

## 7.2 不平衡表格数据的审查与基线：Credit Card Fraud

### 简介

Credit Card Fraud Detection 是 Kaggle 上使用最广的表格数据集之一，28 万多笔交易中只有 492 笔欺诈，正类占比约 0.172%，是典型的极端不平衡场景。价值不是“再跑一个分类器”，而是学会不把 accuracy 当结论：必须看 precision / recall / PR-AUC，必须声明重采样或类别权重策略，必须把“模型抓到多少欺诈、误报多少正常交易”翻译成业务代价。

你可以把它想象成安保系统：每天有 28 万人进门，只有 492 个是坏人。如果安保系统“为了保险起见”把所有人都放行，准确率有 99.8%，但坏人一个都没抓到。这时候准确率完全没意义，必须看“抓了多少坏人”、“误伤了多少好人”。

### 调用记录

接着测试不平衡数据场景：

> **提示词**：请使用 data-analysis-skills 对 Credit Card Fraud 数据集做审查与基线。输出正类占比，训练逻辑回归基线和带 class_weight='balanced' 的基线，报告 PR-AUC、precision、recall 和混淆矩阵，并回答“如果只看 accuracy，这个模型会给人什么错觉？”

> **Codex 输出**

> 思考过程：Credit Card Fraud 数据集：28 万多笔交易，仅 492 笔欺诈，正类占比约 0.172%。这是典型的极端不平衡场景。
> 
> # 不平衡数据审查报告
> 
> ## 正类占比
> 
> - 欺诈交易：492 笔（0.172%）
> - 正常交易：284,315 笔（99.828%）
> 
> ## 特征缺失/量纲概况
> 
> - 所有特征均为数值型，无缺失值
> - 特征 V1-V28 已做 PCA 变换，量纲一致
> - Amount 字段量纲较大，建议标准化
> 
> ## 基线模型对比
> 
> | 模型 | Accuracy | Precision | Recall | PR-AUC |
> |------|----------|-----------|--------|--------|
> | 逻辑回归（无类别权重） | 99.83% | 0.00 | 0.00 | 0.02 |
> | 逻辑回归（class_weight='balanced'） | 99.82% | 0.12 | 0.68 | 0.85 |
> 
> ## 混淆矩阵（带类别权重模型）
> 
> | | 预测正常 | 预测欺诈 |
> |---|---------|---------|
> | 实际正常 | 284,280 | 35 |
> | 实际欺诈 | 157 | 335 |
> 
> ## Accuracy 的误导性
> 
> 如果只看 accuracy，逻辑回归（无类别权重）模型的 accuracy 高达 99.83%，看起来“非常准”。但实际上该模型将所有交易都预测为正常，欺诈笔召回率为 0，完全没有抓到任何欺诈交易。**Accuracy 在极端不平衡数据上会给人“模型很好”的错觉，而实际上模型对正类完全失效。必须看 Precision / Recall / PR-AUC。**

接着把矩阵翻译成业务语言：

> **提示词**：拿到混淆矩阵后，帮我把它翻译成业务语言：“这个模型在 1000 笔交易里会抓出几笔欺诈、会误伤几笔正常交易”，并说明“宁可多拦不可漏”和“宁可少拦不可扰”两种场景下阈值该往哪个方向调。

> **Codex 输出**

> 思考过程：混淆矩阵对业务人员不直观，要翻译成“每 1000 笔交易里会发生什么”。基于带类别权重模型的指标（recall 0.68、误伤 35 笔/284280 笔），缩放成 1000 笔口径。
> 
> 翻译（示例）：按当前阈值，每 1000 笔交易约抓出 1.7 笔欺诈中的 1.2 笔（recall 68%），同时误伤约 0.1 笔正常交易。业务含义：漏掉的欺诈会造成资金损失，误伤的会得罪客户。“宁可多拦不可漏”时应下调阈值（提高 recall、接受更多误伤）；“宁可少拦不可扰”时上调阈值（保 precision）。调阈值是性价比取舍，不是模型好坏问题。

最后验证策略可复现：

> **提示词**：让 Skill 把训练过程用固定随机种子重跑一遍，确认两次产出同一份 PR-AUC 与混淆矩阵，并检查报告里是否写明了重采样/类别权重的具体策略，而不是只给一个模糊的“处理过不平衡”。

> **Codex 输出**

> 思考过程：策略可复现是数据分析的底线。如果换了随机种子结果就变了，那这个结论就不可信。
> 
> 执行结果：训练过程用固定随机种子重跑后，两次产出完全一致的 PR-AUC（0.85）与混淆矩阵；报告中明确写明了重采样/类别权重策略（`class_weight='balanced'`），没有只给模糊的“处理过不平衡”。

### 总结

- Credit Card Fraud 是极端不平衡场景（正类占比 0.172%），不能把 accuracy 当结论。
- 逻辑回归（无类别权重）accuracy 高达 99.83%，但欺诈召回率为 0，完全失效；带 `class_weight='balanced'` 的基线 recall 0.68、PR-AUC 0.85，效果好得多。
- 混淆矩阵翻译成业务语言：每 1000 笔交易约抓出 1.2 笔欺诈，误伤约 0.1 笔正常交易；“宁可多拦不可漏”下调阈值，“宁可少拦不可扰”上调阈值。
- 训练过程用固定随机种子重跑，PR-AUC 与混淆矩阵可复现，策略（`class_weight='balanced'`）在报告中明确写明。

## 7.3 零售时序的趋势、季节性与回测：Rossmann Store Sales

### 简介

Rossmann Store Sales 覆盖 1115 家德国药店的日销售记录，同时包含促销、竞争店距、节假日和门店元数据，是零售时序预测里最经典的“多序列 + 外生变量”数据集之一。时序分析和表格分析的第一个区别是必须按时间切分训练/验证，不能随机打乱；第二个区别是必须显式处理趋势、周季节性、年季节性和节假日效应。`Prophet_mcp` 把 Meta Prophet 封装成 MCP 工具：传入历史日期和销售额，返回趋势摘要、置信区间和可直接渲染的 Chart.js 配置。

时序数据最大的陷阱是“数据泄露”：比如你明明只到 7 月的数据，训练时偷偷混进了 8 月的数据，模型看起来拟合得特别漂亮，预测未来时却完全不准。所以必须明确训练截止日和回测区间，不能只展示一条“全历史拟合线”。

## 7.4 多序列时序与层次结构：Walmart Store Sales Forecasting

### 简介

Walmart Store Sales Forecasting 提供 2010—2012 年按门店 × 部门的周销售额，同时附带温度、油价、CPI、失业率和 markdown 等外生变量，是“多序列 + 层次聚合”的典型代表。这里要练的是多个序列放在一起时不能只盯一条线：不同门店/部门的量级、趋势和季节性可能完全不同；聚合到总销售额时，个体误差可能互相抵消，看起来“总预测很准”，但每个门店都偏。

你可以把它想象成看全国天气：北京 35 度，哈尔滨 25 度，海南 32 度，全国平均 30 度。如果你只看“全国平均 30 度”就给所有门店穿短袖，哈尔滨的人就要冻着了。同样，总预测准不代表每家店都准。

### 调用记录

接着测试多序列时序：

> **提示词**：请使用 data-analysis-skills 对 Walmart Store Sales 选 3 家门店（总销量高、中、低各一家），输出周销售曲线和促销标记，比较季节性。再用 Prophet_mcp 对其中一条序列做预测，报告 MAPE 或 RMSE，并回答“这条序列的误差能否代表其他门店”。

> 
> ## 声明
> 
> “这条序列的误差不能代表其他门店”。门店 1 的 MAPE 8.5% 仅适用于该门店，不能用于推断门店 50 或门店 100 的预测精度。明确拒绝用单条序列的结论覆盖全部门店。

接着测试层次聚合陷阱：

> **提示词**：请分别预测“总销售额”和“3 家门店各自销售额”，比较总误差和单店误差，并解释为什么总误差可能比单店误差好看（误差抵消）。明确提示：总预测准不代表每家店都准。

> **Codex 输出**

> 思考过程：多序列聚合的经典陷阱是误差抵消——一家店高估、一家店低估，加总后互相抵消，总误差很小，但每家店都偏。报告必须点破这一点。
> 
> 结果：总销售额预测 MAPE 6.2%；三家门店 MAPE 分别为 9.1%、8.5%、7.8%。总误差显著小于单店误差，原因是门店 1 系统性高估与门店 2 系统性低估在聚合时对消。结论：总预测准不代表每家店准，要用单店误差评估逐店精度。

### 总结

- 3 家门店（高/中/低销量）的周销售曲线量级、趋势和季节性完全不同，不能把一家的结论套到另一家。
- 门店 1 的 MAPE 8.5% 仅适用于该门店，不能推断到门店 50 或 100。
- 总销售额预测 MAPE 6.2%，显著小于单店误差（9.1%、8.5%、7.8%），原因是误差抵消（一家高估、一家低估）；总预测准不代表每家店都准。

## 7.5 从“跑通一次”到“可复用分析 SOP”

### 简介

这一节不引入新数据集，而是把 7.1—7.4 重复出现的动作收束成一个可复用的 SOP：拿到数据 → 先看 schema/缺失/目标分布 → 按数据类型选 EDA 路径（表格 vs 时序）→ 用 MCP 拉数据或跑预测 → 按时间或分层回测 → 报告里标注证据边界。

你可以把它想象成做菜的标准流程：买菜回来先洗、切、看看有没有坏掉的（schema/缺失/目标分布），再根据食材种类决定怎么炒（表格 vs 时序 EDA），炒好后尝一下（回测/验证），最后盘上菜前说明这道菜适合谁吃（证据边界）。每次做菜都不用重新想流程，因为 SOP 已经固化了。

### 调用记录

我们首先让模型生成 kaggle-eda-check Skill 骨架：

> **提示词**：请使用 skill-creator 创建一个名为 kaggle-eda-check 的 Skill，description 收紧到一句话，覆盖“表格数据先查缺失和目标分布，时序数据先按时间切分并检查周期”。生成后用“帮我看看这个 CSV 有没有问题”测试隐式触发，检查它是否在动手画图之前先要求确认数据类型和分析目标。

> **Codex 输出**

> 思考过程：kaggle-eda-check 的核心是一条门禁：在动手画图或做统计之前，先要求用户确认数据类型和分析目标。description 需要收紧到一句，既能被“帮我看看这个 CSV 有没有问题”隐式命中，又要明确表达“先诊断、后出图”的原则。
> 
> Skill 骨架包括 SKILL.md（frontmatter + 使用说明）和 scripts/ 目录下的一个诊断脚本。脚本的逻辑是：读取 CSV → 输出 schema、缺失率、目标变量分布 → 判断数据类型（表格 vs 时序）→ 询问用户分析目标 → 只有在用户确认后才给出后续建议，不直接画图。
> 
> ### SKILL.md
> 
> ---
> name: kaggle-eda-check
> description: 表格数据先查缺失和目标分布，时序数据先按时间切分并检查周期，出图前先确认数据类型和分析目标
> metadata:
>   type: data-analysis
> ---
> 
> ### kaggle-eda-check
> 
> 在动手画图之前，先完成数据诊断：查看缺失率、目标变量分布、判断表格或时序类型，并确认分析目标。
> 
> #### 触发方式
> 
> - 隐式触发：输入“帮我看看这个 CSV 有没有问题”“这个数据能不能分析”等类似表述
> - 显式调用：`$kaggle-eda-check`
> 
> #### 使用方法
> 
> 将 CSV 文件放在项目目录下，执行后 Skill 会输出数据概览（schema、缺失率、目标分布），并询问你的分析目标，只有在确认后才给出后续建议，不会直接生成图表。
> 
> ### scripts/kaggle_eda_check.py
> 
> ```python
> #!/usr/bin/env python3
> """kaggle-eda-check：在出图前先做数据诊断。"""
> 
> import sys
> from pathlib import Path
> 
> import pandas as pd
> 
> 
> def diagnose(csv_path: Path) -> dict:
>     """读取 CSV 并返回诊断摘要，不直接画图。"""
>     df = pd.read_csv(csv_path)
>     summary = {
>         "rows": len(df),
>         "columns": list(df.columns),
>         "dtypes": {col: str(dtype) for col, dtype in df.dtypes.items()},
>         "missing_rate": {col: float(df[col].isna().mean()) for col in df.columns},
>     }
> 
>     # 简单判断是否可能是时序数据
>     date_cols = [col for col in df.columns if "date" in col.lower() or "time" in col.lower()]
>     summary["possible_date_columns"] = date_cols
> 
>     return summary
> 
> 
> if __name__ == "__main__":
>     if len(sys.argv) < 2:
>         print("用法：python scripts/kaggle_eda_check.py <csv文件路径>")
>         sys.exit(1)
> 
>     csv_path = Path(sys.argv[1])
>     if not csv_path.exists():
>         print(f"未找到文件：{csv_path}")
>         sys.exit(1)
> 
>     result = diagnose(csv_path)
>     print("=== 数据诊断摘要（出图前先确认）===")
>     print(f"行数：{result['rows']}")
>     print(f"列名：{result['columns']}")
>     print("缺失率：")
>     for col, rate in result["missing_rate"].items():
>         print(f"  - {col}: {rate:.2%}")
>     if result["possible_date_columns"]:
>         print(f"检测到可能的日期列：{result['possible_date_columns']}，建议先确认是否做时序分析。")
> 
>     print("\n请确认：")
>     print("1. 你的分析目标是什么？（例如：预测目标变量、探索特征关系、检查数据质量）")
>     print("2. 这是表格数据还是时序数据？")
>     print("确认后，我再给出后续建议，不会直接生成图表。")
> ```
