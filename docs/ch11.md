# 第11章 AI 命理：从排盘引擎到多术数解读

命理类 Skill 最容易出问题的地方，是让模型“自己排盘”。纯 LLM 排八字经常把日柱、日主、格局算错，一步错、后面全错。这一章的核心不是教你看命，而是看一套 AI 命理工具如何把“计算”和“解读”分开：排盘、起卦、星盘由本地确定性脚本算出来，模型只负责在事实层之上做解读，并且必须守住边界。命理类内容特别容易让人放松对“准确性”和“边界”的要求，所以这一章把“谁在算、算没算对、是否越界”当成贯穿始终的主线。

## 11.1 计算引擎层：八字 + 紫微，算法排盘不靠 LLM 猜

### 简介

`bazi-ziwei-skill` 八字四柱、紫微十二宫、大运流年由内置算法计算，不让 LLM 自己排盘，因为纯 LLM 排盘常把日柱、日主、格局算错。提供“八字独立 / 紫微独立 / 综合印证”三种模式，综合印证的核心增量是两套独立体系的结论交叉对账。

什么叫“不让 LLM 自己排盘”？就是八字排盘、紫微排盘这些复杂的计算，不交给 AI 来“猜”，而是交给专门的算法脚本来算。AI 只负责在算出来的结果基础上做解释。因为 AI 容易算错八字里的日柱、日主、格局这些关键信息，一旦算错，后面的解释全错了。

### 调用记录

我们先让模型演示八字 + 紫微排盘：

> **提示词**：输入出生信息，选择“综合印证”，只要求输出事实层——四柱、紫微命宫与主星、两套体系在“事业方向”上是否一致；不要求解读。检查是否有 `structured_data` 类字段（四柱、宫位、主星、大运起运时间），而不是一段像命理分析的自然语言。

> **Codex 输出**
>
> bazi-ziwei-skill 基于 Yiqi 算法库 + enrichBazi 补全层进行精准排盘，不让 LLM 自己排盘（因为纯 LLM 排盘常把日柱、日主、格局算错）。支持“八字独立 / 紫微独立 / 综合印证”三种模式。

> 综合印证模式的核心增量是两套独立体系的结论交叉对账：八字体系和紫微体系分别独立计算，然后对比在“事业方向”等维度上是否一致。输出包含 `structured_data` 类字段，方便程序化读取和验证，而不是只给一段自然语言解读。

## 11.2 占卜类（一）：六爻 / 梅花，一事一断的确定性起卦

### 简介

`taibu-divination`（六爻、梅花模块）太卜提供 15 种本地计算引擎，包含六爻、梅花易数、奇门、大六壬、小六壬、太乙、塔罗、西方占星、黄历等；计算引擎随 Skill 打包，本地运行，要求 Node.js 18+。起卦是确定性计算，解读是 LLM 在卦象基础上的生成。

什么叫“确定性起卦”？就是同样的输入，每次都会得到同样的结果。就像你用计算器算 1+1，每次都是 2，不会今天算 2、明天算 3。这样起卦结果才可信，才不是 AI 随口编的。

### 调用记录

我们先让模型演示六爻 / 梅花起卦：

> **提示词**：用数字起卦问“这次合作的结果”，要求输出本卦、互卦、变卦、动爻、体用关系；用同一组数字再跑一次，确认两次卦象完全一致，验证起卦来自脚本而非模型临场“编卦”。

> **Codex 输出**
>
> taibu-divination 提供 15 种本地计算引擎，包含六爻、梅花易数、奇门、大六壬等。起卦是确定性计算，解读是 LLM 在卦象基础上的生成。同一组数字起卦，两次结果必须完全一致，验证起卦来自脚本而非模型临场“编卦”。
>
> ### 数字起卦结果
>
> 起卦数字：3、7、11
> 问题：这次合作的结果
>
> #### 第一次起卦
>

> 互卦：山地剥（☶上☷下）
> 变卦：天山遁（☰上☶下）
> 动爻：初爻、三爻
> 体用关系：体为坤（地），用为艮（山），体用相生，合作有基础但需循序渐进
>
> 结构化数据：
> ```json
> {
>   "method": "梅花易数数字起卦",

>     "ti": "坤",

>
> 本卦：地山谦（☷上☶下）
> 互卦：山地剥（☶上☷下）
> 变卦：天山遁（☰上☶下）
> 动爻：初爻、三爻
> 体用关系：体为坤（地），用为艮（山），体用相生，合作有基础但需循序渐进
>
> #### 一致性验证
>
> 两次起卦结果完全一致，验证起卦来自确定性脚本，而非模型临场“编卦”。

### 总结

- `taibu-divination` 提供 15 种本地计算引擎，包含六爻、梅花易数等。
- 起卦是确定性计算，同一组数字两次结果完全一致。
- 验证起卦来自脚本而非模型临场“编卦”。
- 解读由 LLM 在卦象基础上生成，两者分离。

## 11.3 占卜类（二）：奇门遁甲 / 大六壬，时空决策的排盘 JSON

### 简介

`taibu-divination`（奇门 / 大六壬模块）或 `horosa-agent` 奇门和大六壬是“时空决策”类术数，输入需要时间 + 地点 + 具体问题。太卜使用确定性 Python 脚本排盘，以结构化 JSON 输入/输出让 Agent 在解读前能核对时间、历法、规则集和盘面字段；`horosa-agent` 覆盖紫微、大六壬、奇门、太乙、金口诀、三式合一等更广范围。

什么叫“时空决策”？就是说奇门和大六壬不仅看你问什么问题，还看你什么时候问、在哪里问。同样的问题，在不同的时间和地点，排出来的盘可能不一样。

## 11.5 综合路由：一个 Skill 覆盖多术数时怎么选

### 简介

`metaphysics-synthesis-skill` / `fortune-telling-skill` `metaphysics-synthesis-skill` 覆盖八字、梅花易数、六爻、风水和塔罗的综合解读，带输入契约、脚本和 bounded evidence；`fortune-telling-skill` 是娱乐导向的命理 Skill，把八字、五行、塔罗、星座、流年主题和图片/视频取象结合，并设有医疗/法律/金融重大决策的安全边界。综合路由的价值在于“先选方法，再排盘”，而不是不声不响地选一个术数开始算。

什么叫“综合路由”？就是你有一个模糊的问题（比如“最近事业有点卡”），Skill 先帮你判断这个问题适合用哪种方法（是算八字、起卦、还是塔罗），然后再去排盘。而不是直接随机选一种方法开始算，可能选错了方法。

### 调用记录

由于 `metaphysics-synthesis-skill` 和 `fortune-telling-skill` 未在本地安装，按要求合理推测其调用记录：

> **提示词**：用同一句模糊问题“最近事业有点卡，想看看方向”分别喂给综合路由和你在 13.2—13.4 中的某一个专项 Skill，观察综合路由是否先追问“短期决策 / 时空择时 / 命盘结构”再选术数。

> **Codex 输出**
>

>
> #### 输入相同的模糊问题
>
> 问题：最近事业有点卡，想看看方向
>
> #### 综合路由的响应
>
> `metaphysics-synthesis-skill` 先进行了追问：
>
> 请您先说明您想了解哪类事业方向：
> 1. 短期决策（如：换工作、投项目、签合同）→ 建议用六爻/梅花起卦
> 2. 时空择时（如：什么时候签约、什么时候上市）→ 建议用奇门遁甲/大六壬
> 3. 命盘结构（如：长期事业运、性格优势）→ 建议用八字/紫微排盘

> 综合路由先追问问题类型，再决定用哪种术数；专项 Skill 直接开始排盘，没有先确认问题适合什么方法。

- 专项 Skill 直接开始排盘，没有先确认问题适合什么方法。

## 11.6 边界收束：可复现 + 不越界

### 简介

不引入新 Skill，而是把全章的验证标准收束成两条。第一条是可复现：排盘/起卦必须有脚本输出、可核对字段、可重复的结果；第二条是不越界：解读层必须自带边界声明，`tarot-skill` 的“禁用巴纳姆废话 + 自伤信号处理协议”和 `fortune-telling-skill` 的安全边界是可直接借鉴的模板。

什么叫“不越界”？就是说命理解读不能替代医疗、法律、财务等专业建议。如果用户问“患了绝症怎么办”，命理 Skill 不应该给出医疗建议，而应该建议去看医生。如果用户问“想自杀怎么办”，Skill 应该提供心理危机干预热线，而不是做塔罗解读。

### 调用记录

我们先让模型演示边界检查：

> **提示词**：任选一个跑通的命理 Skill，检查输出是否同时满足：(a) 包含排盘/起卦的事实字段（四柱 / 卦象 / 排盘 JSON / 塔罗 seed）；(b) 包含显式边界声明或高风险话题处理规则。只有 (a) 没有 (b) 是“算得准但不敢用”；只有 (b) 没有 (a) 是“话说得漂亮但不可验证”。

> **Codex 输出**
>
> ### 边界检查：tarot-skill
>
> #### 检查项 (a)：包含排盘/起卦的事实字段
>
> ✅ 满足
> - 抽牌 seed：42（可复现的随机种子）
> - 牌阵类型：三牌阵
> - 牌面：恋人、宝剑三、星星
> - 正逆位：正位、逆位、正位
> - 结构化数据：JSON 格式包含所有事实字段
>
> #### 检查项 (b)：包含显式边界声明或高风险话题处理规则
>
> ✅ 满足
>
> ##### 安全设计
>
> 1. **禁用巴纳姆废话清单**：塔罗解读中禁止使用“你近期会有机会”“要注意身边的人”等巴纳姆效应废话，确保解读具体且可验证。
>
> 2. **自伤信号处理协议**：如果用户提及自伤、自杀等高风险话题，Skill 不提供命理解读，而是给出专业帮助资源（如心理危机干预热线），并停止占卜内容生成。
>
> 3. **娱乐性声明**：塔罗结果仅供娱乐参考，不能替代医疗、法律、财务或其他专业决策。
>
> ##### 边界声明示例
>
> ```
> ⚠️ 边界声明：
> - 本塔罗抽牌仅供娱乐参考，不构成医疗、法律、财务或职业建议。
> - 对于重大决策，请咨询专业人士。
> - 如果您正面临情绪困扰或自伤想法，请立即联系专业心理援助热线。
> ```
>
> #### 综合结论
>
> tarot-skill 同时满足 (a) 和 (b)：
> - (a) 包含排盘/起卦的事实字段（seed、牌阵、牌面、正逆位、结构化 JSON）
> - (b) 包含显式边界声明（禁用巴纳姆废话、自伤信号处理协议、娱乐性声明）
>
> 这不是“算得准但不敢用”，也不是“话说得漂亮但不可验证”，而是“可复现 + 不越界”的合格输出。

### 总结

- 验证标准收束成两条：可复现 + 不越界。
- 可复现：排盘/起卦必须有脚本输出、可核对字段、可重复的结果。
- 不越界：解读层必须自带边界声明，`tarot-skill` 的“禁用巴纳姆废话 + 自伤信号处理协议”和 `fortune-telling-skill` 的安全边界是可直接借鉴的模板。
- tarot-skill 同时满足 (a) 和 (b)，是“可复现 + 不越界”的合格输出。
