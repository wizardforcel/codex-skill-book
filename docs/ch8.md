# 第8章 编写论文

写论文最忌讳一上来就写：类型没定、章节没排、文献没核，写出来的东西大概率要重来。这一章的两个 Skill 一个管“中文优先的学术写作流程”，一个管“数学建模竞赛论文的格式合规与交付安全”。它们的共同点是把“先确认再写作”“先检查再交付”固化成流程，而不是让你把一段提示词扔给模型的运气游戏。写论文最怕一边写一边改类型和工作量，所以先把类型与结构确认清楚再动笔，返工率会低很多，心态也稳。

## 8.1 中文优先的学术写作与学位论文

### 简介

`research-writing-skill`（技能名 `research-writing-assistant`）是中文优先的学术写作 Skill，覆盖头脑风暴、章节写作、文献综述、Python 图表和 LaTeX 输出，支持“帮我写毕业论文”这类隐式触发。它把写作拆成一组子技能：入口路由、整篇任务编排、7 轮问答的头脑风暴、章节写作、LaTeX 输出、文献综述、证据驱动写作、验证等。学术写作的返工往往来自开头没谈清楚类型和结构，这套技能把'先确认再写'变成一条硬要求，而不是一句建议。

它的价值在于把中文学术写作的规范内置到过程里，而不是先出英文再翻译。它有两条硬规则：任何论文任务开始前必须先调入口技能；不允许跳过头脑风暴直接写作。

### 调用记录

**我**：帮我写一篇深度学习图像分割的毕业论文引言，约 500 字。

**Codex**：入口技能 `using-research-writing` 的 Red Flags 直接命中两条：

```text
"用户说得很清楚了，直接开始写" → 必须先完成 brainstorming-research
"我很确信"                      → 确信 ≠ 证据，运行验证
```

所以它不会先写一段引言，而是进入头脑风暴。

**我**：为什么 500 字引言也要先聊？

**Codex**：因为`brainstorming-research/SKILL.md` 写了一条 HARD-GATE：

```text
在完成所有问答并获得用户最终确认之前，禁止：
- 写任何正文内容
- 创建 chapters/ 目录
- 调用 writing-chapters 技能
- 输出任何论文章节的实际内容
```

再简单的项目也要过流程，因为“简单”往往藏着最多的未检验假设。它还规定了交互方式：**一次只问一个问题**，等待回答再问下一个，而且要“给推荐、让用户确认”，不能甩一张表格让用户填。

**我**：那它第一句会问什么？

**Codex**：按 checklist，第一个问题是论文类型：

> 你这次要写的是什么类型的论文？
> - 毕业论文（本科 / 硕士 / 博士）
> - 期刊投稿（中文核心 / SCI）
> - 会议论文
> - 课程论文或报告
>
> 不同类型的论文在篇幅、结构和语言风格上有差异，我需要先了解这个来帮你规划。

**我**：硕士毕业论文，工科。

**Codex**：接下来依次确认学科领域（工科侧重技术方案与实验验证）、论文题目、研究背景与目的、研究方法，再检测是否用 LaTeX 模板，然后按论文类型给出标准章节结构让你确认，最后汇总所有信息获得最终确认——全部确认后才创建 `plan/` 和 `chapters/`，并问从哪一章开始。即使最终只写 500 字引言，前面这些确认也决定它长什么样。

**我**：如果它查文献呢？

**Codex**：文献受“证据优先于声称”约束，Red Flags 明确“绝不编造文献，必须可追溯”“没有来源的引用一律不写”，并有验证技能会把引用拿去核对。这是和普通聊天最大的区别。

**我**：这一步有没有什么容易被忽略的细节？

**Codex**：最常见的是跳过环境验证就宣称可编译：本机没有 LaTeX 时，任何'已经编译通过'都是假的。先别怀疑工具本身，多数情况是环境、路径或前置条件没对上。

把这一节放回整条链路里看，它只是其中一段；真正动手时不必追求一次全对，先把命令跑通、把输出对上，遇到报错再回来查对应位置，往往比从头读一遍更快。

### 总结

这一节的内容说起来不少，真正值得带走的是下面几条；把它们串起来看一遍，比单独记某一条更有用。

- `research-writing-skill` 是中文优先的分层技能集，覆盖头脑风暴到 LaTeX 输出。
- 任何论文任务先走入口路由，不允许跳过头脑风暴直接写正文。
- 头脑风暴是对话式的：一次一个问题、给推荐让确认，全部确认前 HARD-GATE 禁写正文。
- 论文类型决定语言与结构；文献必须可追溯，编造文献是被禁止的。
- “写 500 字引言”同样要过流程，因为流程检验的正是那些隐藏假设。

## 8.2 数学建模竞赛论文的模板与检查

### 简介

`mathmodel-latex-skill` 面向 MCM/ICM、CUMCM 的 LaTeX 论文，解决竞赛特有的“格式合规 + 交付安全”：LaTeX 编译预检、匿名检查、引用/关键词校验和 CUMCM 优秀论文风格规则。它区分两种竞赛：带 team control number 的多半是 MCM/ICM；带承诺书、编号专用页、中文摘要、支撑材料的多半是 CUMCM。竞赛论文最怕的是格式一票否决，把检查做成脚本，等于在交付前多了一道不依赖审稿人的闸门。

它坚持“不伪造”：不发明官方当年的页数/字体/规则，不插入真实学校姓名，不用在线包和网络下载当编译步骤。

### 调用记录

**我**：生成一个空的 CUMCM 竞赛论文模板，然后在里面故意留一个 `\cite{missing}`。

**Codex**：先从 `templates/cumcm/` 复制模板到测试目录，往 `main.tex` 追加一行：

```latex
引用了不存在的文献 \cite{missing}。
```

然后按技能要求先做环境预检：

```powershell
python scripts/check_latex_env.py --contest cumcm --use-ref-bib
# ERROR: kpsewhich not found. Install TeX Live or MiKTeX and ensure it is on PATH.
```

本机没有 LaTeX（`pdflatex`/`xelatex` 都不存在，`kpsewhich` 也找不到），所以编译环节被真实阻断。

**我**：那把 PDF 编译不了，检查脚本还能不能发现问题？

**Codex**：能。运行引用检查脚本：

```powershell
python scripts/check_latex_refs.py main.tex --bib ref.bib
# MISSING CITATION KEYS:
# - missing
# FAILED
```

它如实报出了未定义引用，而且退出状态表示失败——这正是技能要的“交付安全”：不让它静默编译出一个带问号的 PDF。再跑 CUMCM 关键词检查：

```powershell
python scripts/check_latex_keywords.py main.tex
# PASSED: 4 modeling keywords checked
```

**我**：为什么这类 Skill 这么较真“检查”？

**Codex**：因为竞赛论文最怕的是格式一票否决：匿名信息泄漏、引用没定义、关键词是背景词、图表编号错乱。技能把这些检查做成脚本，在编译/交付前跑一遍，红线写死在规则里——不写真实身份、不用 `\nocite{placeholder}`、CUMCM 不用 pdfLaTeX 编译中文模板，等等。

**我**：如果第一次没跑通，通常先查哪里？

**Codex**：最常见的是跳过环境验证就宣称可编译：本机没有 LaTeX 时，任何'已经编译通过'都是假的。把这一步记下来，下次再遇到同类问题时能少走不少弯路。

这些步骤看起来零散，其实前后是有因果的：前一步的产物就是后一步的输入，中间哪一环没对上，后面就会以各种奇怪的方式报错。

### 总结

这一节的内容说起来不少，真正值得带走的是下面几条；把它们串起来看一遍，比单独记某一条更有用。

- `mathmodel-latex-skill` 覆盖 MCM/ICM 与 CUMCM 两种竞赛，靠字段特征自动识别。
- `check_latex_env.py` 做环境预检；本机缺 LaTeX 时它如实报 `kpsewhich not found`。
- `check_latex_refs.py` 能在编译前发现 `\cite{missing}`，输出 `MISSING CITATION KEYS` 并以失败退出。
- `check_latex_keywords.py` 校验关键词必须是建模术语，不能是题目背景词。
- 竞赛模板默认匿名：不填真实校名/姓名，不依赖网络与在线包。

## 8.3 从零生成骨架与可编译初稿

### 简介

端到端的论文链路是：研究主题 → 章节骨架 → 引用格式 → LaTeX 输出。这一节拿“基于图神经网络的推荐系统”做示例，走一遍骨架生成，并验证“可编译”这一环。规划里提到的 `academic-researcher` 技能经过实测：`npx skills add academic-researcher-skill` 报 `repository 'academic-researcher-skill' does not exist`，当前名下的仓库不可用，因此以 `research-writing-skill` 的 LaTeX 输出能力作为主线，并把这一真实失败写进记录。从研究主题到可编译的论文，中间隔着骨架、引用格式和环境验证；只有每一步都真实存在，你才能判断那条链路到底行不行。

### 调用记录

**我**：给定题目“基于图神经网络的推荐系统”，要求输出带三级标题 + 每节预期字数的骨架，并给一个能 `pdflatex` 编译的最小 `.tex`。

**Codex**：先按 8.1 的头脑风暴确认论文类型与结构。课题型论文的骨架示例（期望字数为示意值，需在写作中按实际调整）：

```markdown
# 基于图神经网络的推荐系统

## 摘要
- 目的：一句话背景 + 一句话问题（约 150 字）
- 方法：模型与数据集（约 200 字）
- 结果：关键指标（约 100 字）

## 1 引言
- 1.1 研究背景（约 300 字）
- 1.2 研究现状与不足（约 400 字）
- 1.3 本文工作与组织（约 200 字）

## 2 相关工作
- 2.1 传统推荐方法（约 300 字）
- 2.2 图神经网络（约 300 字）

## 3 方法
- 3.1 问题定义（约 200 字）
- 3.2 模型框架（约 400 字）
- 3.3 学习与推理（约 300 字）

## 4 实验
- 4.1 数据集与基线（约 250 字）
- 4.2 结果与分析（约 350 字）

## 5 结论与展望（约 200 字）
```

**我**：`.tex` 能编译吗？

**Codex**：本机实测不能——8.2 已确认没有 LaTeX 工具：

```text
kpsewhich not found. Install TeX Live or MiKTeX and ensure it is on PATH.
```

所以“可编译”这一环的真实结论是：骨架和 `.tex` 文件能由 Skill 生成，但编译验证需要一个装好 TeX Live 或 MiKTeX 的环境，例如：

```bash
latexmk -xelatex main.tex
```

在读者的机器上补上 LaTeX 后，这条命令即应得出一份包含三级标题的 PDF。没有 LaTeX 的环境里，任何声称“已经编译通过”都是假的——这正是这一节要教你的：验证动作要真的能跑起来，而不是假设它行。

**我**：搜索 MCP 能找到 academic-researcher 的公开教程吗？

**Codex**：没有检索到可用的项目教程，这也和安装时的报错一致——`npx skills add academic-researcher-skill` 返回仓库不存在。检索不到不等于内容不存在，但在本书里必须如实处理：不拿别的论文 Skill 冒充它，改用已经验证可用的 `research-writing-skill` 走骨架与 LaTeX 输出。

**我**：按这个流程做，最容易卡在哪一步？

**Codex**：最常见的是跳过环境验证就宣称可编译：本机没有 LaTeX 时，任何'已经编译通过'都是假的。遇到时先按本节记录的顺序排查，通常都能定位到具体原因。

如果只记住一句，那就是：先让最小链路真实跑通，再谈优化和自动化；跳过验证直接堆功能，最后往往要花更多时间回头补。

### 总结

这一节的内容说起来不少，真正值得带走的是下面几条；把它们串起来看一遍，比单独记某一条更有用。

- 论文链路 = 主题 → 骨架 → 引用格式 → LaTeX 输出，骨架要先体现论证层次与预期字数。
- `academic-researcher` 当前经实测不可安装（仓库不存在），主线用 `research-writing-skill` 的 LaTeX 输出。
- 三级骨架的每节字数要和章节作用相匹配，引言负责立题、方法负责讲机制、实验负责给证据。
- “可编译”需要真实的环境验证；缺 LaTeX 时应如实报告，并给出 `latexmk -xelatex main.tex` 这类验证命令。
