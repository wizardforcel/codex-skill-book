# 思辨区规则

这是 `10_正式库/02_思辨区` 的区域规则。规则文件统一存放在 `00_规则`，本文件只保留思辨区特有的导航、提炼链路和调用边界。

## 1. 区域定位

思辨区用于处理从原始聊天、长期问题、自我分析中提炼出的材料。

注意：思辨区材料必须按标签、frontmatter 和提炼状态区分可信度，不能整体视为已核实知识库。

## 2. 区域结构

```text
00_思辨MOC/
01_思辨记录/
02_提炼卡片/
03_Projects/
04_Areas/
05_Inbox/
06_Archive/
07_输出池/
```

## 3. 入口顺序

AI 进入思辨区时，应先读：

```text
10_正式库/02_思辨区/00_思辨MOC/00_思辨区索引.md
10_正式库/02_思辨区/00_思辨MOC/Obsidian总导读.md
10_正式库/02_思辨区/00_思辨MOC/核心观点卡片索引.md
10_正式库/02_思辨区/00_思辨MOC/主题簇导读.md
```

然后再按任务进入具体文件夹。

## 4. 调用边界

正式调用的允许和排除条件统一遵守：

```text
00_规则/06_AI调用过滤与标签检索规则.md
```

思辨区额外边界：

```text
01_思辨记录 和 05_Inbox 默认只能用于追溯或待整理。
原始聊天本身不能直接作为稳定判断。
完成提炼的原始记录仍只是 source，稳定判断以正式卡片或正式笔记为准。
```

完成提炼后，原始记录应改为：

```text
summary: 一句话概括本文件最重要的讨论内容
extract_status: done
extract_depth: content_level
#对话/已提炼
```

这里的“已提炼”不是文件级分类，而是内容级提炼。AI 必须基于原始正文提取本文件实际讨论的主要议题、核心观点、可复用判断、后续去向和污染风险；只根据文件名或速览写一句摘要，不允许标记为已提炼。

思辨类正式卡片或已提炼原始记录必须有固定段落：

```text
## 核心观点
```

`summary` 用于第一轮命中，`## 核心观点` 用于第二轮判断是否值得打开全文。不要把核心观点只藏在长原文末尾。

## 5. 思辨处理链路

```text
原始聊天
-> 内容级提炼
-> 提炼卡片/项目/输出候选
-> 用户放行
-> 正式入库
```
