# 混合检索与向量索引规则

本文件定义正式库的混合检索规则。

核心原则：

```text
00_规则 决定能不能用。
正式库索引负责更快找到候选内容。
向量检索只辅助召回，不替代标签、frontmatter、MOC 和原文核验。
```

## 1. 索引位置

正式库混合检索索引放在：

```text
10_正式库/00_检索索引/
```

主要文件：

```text
README.md：索引使用说明
build_hybrid_index.py：重建索引脚本
search_hybrid.py：混合检索脚本
chunks.jsonl：Markdown 切块和 metadata
vectors.npy：本地向量矩阵
bm25_tokens.json：关键词/BM25 数据
metadata.json：索引构建摘要
excluded_files.json：被规则排除的文件
构建报告.md：人可读构建报告
```

索引文件不是知识正文，不作为最终回答依据。

## 2. 默认索引范围

默认只对 `10_正式库` 中可调用或可导航的 Markdown 建索引。

优先进入索引：

```text
10_正式库/01_笔记区
10_正式库/02_思辨区/02_提炼卡片
10_正式库/02_思辨区/00_思辨MOC
10_正式库/03_项目区
10_正式库/04_每日日志
```

`00_思辨MOC`、正式库索引和区域索引可以进入索引，但角色只能是导航，不是最终结论来源。

默认排除：

```text
10_正式库/00_检索索引
10_正式库/02_思辨区_待整理
10_正式库/02_思辨区/01_思辨记录
10_正式库/02_思辨区/05_Inbox
10_正式库/02_思辨区/06_Archive
旧候选记录
01_导入原始材料
02_入库处理区
99_垃圾区
```

出现以下状态或标签时也排除：

```text
type: inbox
status: raw
status: ai_generated 且未人工允许
truth_status: unverified
truth_status: discarded
#入库/待确认
#入库/拒绝
#归类/待归类
#对话/待提炼
```

## 3. 切块规则

切块只用于检索索引，原始 MD 不拆分、不改写。

```text
短文档：整篇作为一个 chunk。
中等文档：优先按 Markdown 标题切块。
长文档：先按标题切，再按长度细分，并保留少量重叠。
导航/MOC：可以切块，但只作为路由线索。
```

每个 chunk 必须带 metadata：

```text
path
title
heading
doc_role
type
status
truth_status
project_status
summary
tags
chunk_index
```

## 4. 混合检索顺序

正式库调用时按以下顺序：

```text
1. 读 00_规则/00_AI工作入口.md。
2. 读 00_规则/06_AI调用过滤与标签检索规则.md。
3. 读本文件。
4. 判断目标区域，读取 00_规则/12/13/14/15/16 中的相关规则。
5. 先看正式库索引、区域索引、MOC、Bases 缩小范围。
6. 对允许范围使用混合检索索引召回候选 chunk。
7. 合并关键词/BM25、向量相似度、标题/summary 命中和 doc_role 权重。
8. 用 path、type、status、truth_status、project_status、tags 再过滤。
9. 打开原始 MD 文件核验正文。
10. 必要时追溯 source。
11. 回答时说明可信边界或过期风险。
```

禁止只看 chunk 片段就直接下结论。

## 5. 角色权重

检索结果按角色分层使用：

```text
stable_card：优先作为思辨区稳定观点来源。
formal_note：可作为正式笔记来源。
project：可作为项目知识来源。
reference：可作为参考资料来源，事实性内容注意 last_verified。
daily_log：可作为时间线和工作记录，不默认当长期结论。
navigation：只用于缩小范围和进入真实材料。
source_trace：只用于追溯，不优先作为最终结论。
```

如果向量结果命中 `navigation`，必须继续打开它指向的真实卡片或笔记。

如果向量结果命中 `source_trace`，必须确认是否已有正式卡片、正式笔记或项目主页承接该来源。

## 6. 向量层边界

当前索引使用离线本地向量层：

```text
algorithm: hash_tfidf_v1_local
```

它能提升相关内容召回，但不是深度语义 embedding。

后续如果接入 embedding 模型，只替换向量生成方式；索引范围、metadata 过滤、原文核验规则不变。

## 7. 重建时机

以下情况需要重建索引：

```text
正式库新增、移动、删除 Markdown。
文件 frontmatter、summary、tags、truth_status 明显变化。
思辨记录被提炼成正式卡片。
MOC/索引大幅更新。
项目主页或参考资料更新。
```

重建索引不等于修改知识库，只是刷新检索入口。

## 8. 冲突处理

```text
metadata 与向量命中冲突时，以 metadata 为准。
summary 与正文冲突时，以正文和 source 为准。
MOC 与真实卡片冲突时，以真实卡片和 source 为准。
旧结论与新结论冲突时，不直接覆盖，按 conflict_policy 标记复核。
```
