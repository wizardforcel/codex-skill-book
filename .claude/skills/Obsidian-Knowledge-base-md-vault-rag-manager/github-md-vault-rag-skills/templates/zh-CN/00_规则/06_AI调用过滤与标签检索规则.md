# AI 调用过滤与标签检索规则

AI 正式调用时，不应全库扫描。应先限定文件夹，再按标签和 frontmatter 过滤。

AI 检索优化原则见：

```text
00_规则/17_知识库建设与检索优化规则.md
00_规则/18_混合检索与向量索引规则.md
```

## 1. 默认允许调用

```text
10_正式库
#入库/已入库
#归类/已归类
status: reviewed
status: evergreen
truth_status: self_confirmed
truth_status: source_backed
summary: 已填写
```

## 2. 默认禁止调用

```text
01_导入原始材料
02_入库处理区
99_垃圾区
#入库/待确认
#入库/拒绝
#归类/待归类
#对话/待提炼
type: inbox
status: raw
status: ai_generated 且未人工允许
truth_status: unverified
truth_status: discarded
05_Inbox
10_正式库/02_思辨区 中未完成入库标记的内容
```

## 3. 文件夹内按标签检索

可以做到“只在某个文件夹里按标签检索”。

逻辑是：

```text
先限定路径范围
再搜索标签或 frontmatter 字段
只打开命中的文件
```

例如只在正式库里找已入库文件：

```powershell
Get-ChildItem -Path "10_正式库" -Recurse -Filter *.md |
  Select-String -Pattern "入库/已入库"
```

只在待归类队列里找允许入库的文件：

```powershell
Get-ChildItem -Path "02_入库处理区/03_待归类" -Recurse -Filter *.md |
  Select-String -Pattern "入库/允许|归类/待归类"
```

这不是全库扫描，而是“文件夹范围内检索”。日常使用时优先查 Bases 状态视图；AI 作业时优先读索引和区域规则，再按标签/frontmatter 命中文件。

## 4. 正式回答的检索顺序

```text
读 00_规则/00_AI工作入口.md
读相关规则
读 00_规则/18_混合检索与向量索引规则.md
读 00_规则 中对应目标区域的区域规则
读目标区域索引/MOC/Bases
限定任务文件夹
按 type/status/truth_status/project_status/tags 过滤
先读标题、summary、aliases、keywords、核心观点
必要时使用 10_正式库/00_检索索引 做 BM25 + 向量辅助召回
只打开候选文件正文
必要时追溯 source 原始来源
生成回答
```

混合检索结果仍必须接受本文件的允许/禁止规则过滤。命中 chunk 不等于允许调用，最终依据必须回到原始 MD。

## 5. 区域规则优先

如果任务进入正式库，AI 必须先读：

```text
00_规则/12_正式库入口规则.md
```

如果继续进入笔记区或思辨区，再读：

```text
00_规则/13_笔记区规则.md
00_规则/14_思辨区规则.md
```

## 6. Bases 视图

日常审核优先使用：

```text
00_规则/09_入库审核.base
```

正式库状态查看优先使用：

```text
00_规则/10_全库状态.base
10_正式库/01_笔记区/00_笔记区状态.base
10_正式库/02_思辨区/00_思辨区状态.base
```

Bases 自动读取文件标签和 properties。标签/frontmatter 仍然是唯一真实状态。

## 7. 摘要优先

新建或整理正式可调用内容时，必须补 `summary` 字段。

```text
summary 用一句话回答：这篇文件解决什么问题，什么时候该打开。
AI 检索时先看 summary，不因标题相似就直接读全文。
summary 与正文冲突时，以正文和 source 为准，并标记需要复核。
```

## 8. 过期内容处理

高时效内容应补：

```text
last_verified
valid_until
```

到期或未验证内容默认降级为待复核，只能作为线索，不能直接作为稳定判断。
