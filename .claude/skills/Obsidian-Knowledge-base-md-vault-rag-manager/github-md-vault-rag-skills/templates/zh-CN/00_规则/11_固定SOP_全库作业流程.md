# 固定 SOP：全库作业流程

本文件是 AI 处理本库时的固定作业顺序。任何任务都先按本 SOP 分流，再读取对应规则和区域规则。

## 0. 总原则

```text
先分流，再处理。
先看状态，再动文件。
人工辅助模式：先做候选，再等人工闸门。
全自动模式：鉴别后直接入库或废弃，无候选阶段。
提炼完成不等于正式入库。
原始记录只作 source，稳定判断以正式卡片/正式笔记为准。
正式条目必须能通过 summary、type、status、truth_status 快速过滤。
```

AI 每次作业前必须先判断任务属于哪一类：

```text
A. 导入新材料（人工辅助模式）
B. 处理入库候选
C. 归类人工已允许材料
D. 提炼思辨原始记录
E. 正式库调用/回答问题
F. 清理垃圾或污染内容
G. 初始化空库
H. 导入新材料（全自动模式）
I. 模型首次接入/引导生成
```

不要跳过分流步骤。

## 1. SOP-A：导入新材料

适用场景：

```text
用户把新文件、新聊天、新资料扔进库里。
```

作业顺序：

```text
01_导入原始材料
-> 判断项目/非项目
-> 02_入库处理区/01_整理报告
-> 垃圾鉴别
-> 02_入库处理区/02_入库候选
-> 打 #入库/待确认
```

产物：

```text
整理报告
候选成品
建议 route_target
垃圾鉴别结果
```

禁止：

```text
不能直接放入 10_正式库。
不能直接打 #入库/已入库。
不能跳过垃圾鉴别。
```

## 2. SOP-B：人工审核候选

适用场景：

```text
02_入库处理区/02_入库候选 中已有 #入库/待确认 文件。
```

用户只需要改标签：

```text
#入库/允许
#入库/拒绝
```

AI 后续动作：

```text
看到 #入库/允许
-> 补字段
-> 检查 route_target
-> 移入 02_入库处理区/03_待归类
-> 打 #归类/待归类

看到 #入库/拒绝
-> 移入 99_垃圾区
-> truth_status: discarded
```

禁止：

```text
AI 不能替用户把 #入库/待确认 改成 #入库/允许。
```

## 3. SOP-C：正式归类入库

适用场景：

```text
文件已经有 #入库/允许 或处于 02_入库处理区/03_待归类。
```

作业顺序：

```text
读取 route_target
-> 判断正式库区域
-> 读取目标区域规则
-> 移动到 10_正式库 对应位置
-> 补正式入库 frontmatter
-> 改为 #入库/已入库 + #归类/已归类
```

正式入库最低条件：

```text
summary: 一句话摘要
status: reviewed
truth_status: self_confirmed 或 source_backed
review: done
#入库/已入库
#归类/已归类
last_reviewed
```

## 4. SOP-D：思辨原始记录提炼

适用场景：

```text
处理 10_正式库/02_思辨区/01_思辨记录 中的原始聊天。
```

作业顺序：

```text
读取 00_规则
-> 读取 00_规则/14_思辨区规则.md
-> 只进入 01_思辨记录
-> 读取原始正文
-> 做内容级提炼
-> 写议题索引
-> 写核心观点
-> 写可复用判断
-> 写转化去向
-> 写污染风险与调用限制
-> 改为 extract_status: done + extract_depth: content_level + #对话/已提炼
```

内容级提炼最低标准：

```text
必须覆盖本文件实际讨论的主要议题。
必须补 summary 和 ## 核心观点，方便 AI 先判断相关性。
必须保留议题索引，方便追溯原文。
必须区分可复用判断和污染风险。
必须说明后续应该转成卡片、项目、Areas 还是输出。
```

关键区分：

```text
#对话/已提炼 只代表原始聊天已完成内容级整理。
#对话/已提炼 不代表这个原始文件可以作为正式知识调用。
原始聊天仍然只作为 source 追溯。
```

后续转化：

```text
内容级提炼
-> 生成主题卡片/项目/输出候选
-> #入库/待确认
-> 用户放行
-> 正式入库
```

禁止：

```text
不能只根据文件名、旧速览、旧索引写一句摘要就标记 #对话/已提炼。
不能把原始聊天本身当成稳定判断。
不能批量制造低质量卡片污染正式库。
```

## 5. SOP-E：正式库调用

适用场景：

```text
用户让 AI 回答问题、查知识库、调用已有材料。
```

作业顺序：

```text
读取 00_规则
-> 判断目标区域
-> 读取 00_规则/12_正式库入口规则.md
-> 需要混合检索时读取 00_规则/18_混合检索与向量索引规则.md
-> 读取 00_规则 中对应区域规则
-> 先看索引/MOC/Bases 缩小范围
-> 按 type/status/truth_status/project_status/tags 过滤
-> 必要时使用 10_正式库/00_检索索引 做 BM25 + 向量辅助召回
-> 先看标题、summary、aliases、keywords、核心观点
-> 优先打开正式卡片/正式笔记
-> 必要时追溯 source 原始记录
```

允许作为正式依据：

```text
#入库/已入库
#归类/已归类
status: reviewed 或 evergreen
truth_status: self_confirmed 或 source_backed
```

禁止作为正式依据：

```text
#入库/待确认
#入库/拒绝
#归类/待归类
truth_status: unverified
truth_status: discarded
99_垃圾区
原始聊天本身
```

## 6. SOP-F：垃圾和污染处理

适用场景：

```text
发现 AI 跑偏、谄媚、事实不准、重复废话、无来源判断、用户拒绝入库。
```

作业顺序：

```text
标记 #入库/拒绝
-> 写明垃圾鉴别原因
-> 移入 99_垃圾区
-> truth_status: discarded
```

垃圾区用途：

```text
只能作为反面样本或污染追溯。
不能作为知识依据。
```

## 7. 状态同步

状态来源：

```text
frontmatter 和 tags 是真实状态。
Bases 只是动态视图。
MOC/索引只是导航。
混合检索索引只是召回候选。
规则文件才定义流程。
```

每次批量处理后，AI 必须复核：

```text
标签是否符合阶段
route_target 是否存在（仅人工辅助模式）
summary 是否能说明何时打开文件
truth_status 是否可信
last_verified / valid_until 是否已过期
是否误把待确认内容放进正式库
是否误把原始记录当成正式知识
Bases 视图字段是否能看到关键状态
```

## 8. SOP-G：初始化空库

适用场景：

```text
只有 00_规则 文件夹存在，其他文件夹尚未创建。
```

作业顺序：

```text
按 00_规则/01_规则总览.md 创建外层文件夹：
  01_导入原始材料/
    项目/
    非项目/
  02_入库处理区/
    01_整理报告/
    02_入库候选/
    03_待归类/
  10_正式库/
  99_垃圾区/

按 00_规则/12_正式库入口规则.md 创建正式库子文件夹：
  10_正式库/01_笔记区/
  10_正式库/02_思辨区/
  10_正式库/02_思辨区_待整理/
  10_正式库/03_项目区/
  10_正式库/04_每日日志/

按 00_规则/14_思辨区规则.md 创建思辨区子文件夹：
  10_正式库/02_思辨区/00_思辨MOC/
  10_正式库/02_思辨区/01_思辨记录/
  10_正式库/02_思辨区/02_提炼卡片/
  10_正式库/02_思辨区/03_Projects/
  10_正式库/02_思辨区/04_Areas/
  10_正式库/02_思辨区/05_Inbox/
  10_正式库/02_思辨区/06_Archive/
  10_正式库/02_思辨区/07_输出池/

创建占位索引文件（只写文件名和一行说明，不写内容）：
  10_正式库/00_正式库索引.md
  10_正式库/01_笔记区/00_笔记区索引.md
  10_正式库/02_思辨区/00_思辨MOC/00_思辨区索引.md
```

禁止：

```text
不创建任何内容文件，只建骨架。
不提前写任何规则或模板到内容区域，规则只放 00_规则。
不读取不存在的索引文件——初始化阶段这些文件由 AI 自己创建。
```

完成后，向用户说明骨架已建好，并询问工作模式：

```text
【选择工作模式】

A. 人工辅助模式（默认）
   AI 整理材料并生成候选成品，你手动打 #入库/允许 或 #入库/拒绝 决定是否入库。

B. 全自动模式
   AI 自行完成整理、鉴别、入库判断和归类的全部过程，不等待人工确认。
   适合快速处理大量材料，接受一定的误判风险。

请告知选择 A 或 B，或直接开始向 01_导入原始材料 投入材料（默认使用 A）。
```

## 9. SOP-H：全自动模式

适用场景：

```text
用户在初始化后选择了全自动模式，或在任意时刻明确说"全自动处理"。
```

全自动模式跳过所有人工等待环节（候选成品、整理报告、#入库/待确认、#入库/允许）。
流程压缩为三步：导入 -> 鉴别 -> 直接入库或废弃。

作业顺序：

```text
读取 01_导入原始材料 中的文件
-> 执行垃圾鉴别七项检查
-> 鉴别通过或保留：直接写入 10_正式库 对应位置，打 #入库/已入库 #归类/已归类
-> 鉴别废弃：移入 99_垃圾区，truth_status: discarded
-> 七项检查触发 3 项及以上：不强行入库，列入摘要"需人工确认"
```

入库时使用的 frontmatter：

```yaml
status: reviewed
truth_status: source_backed
review: done
confidence: medium
```

不需要填写：route_target、route_reason、review: pending、#入库/待确认、#入库/允许。
这些字段只服务于人工审核流程，全自动模式中省略。

完成后输出处理摘要：

```text
已入库：X 条（列标题 + 入库位置）
已废弃：X 条（列标题 + 废弃原因）
需人工确认：X 条（列标题 + 触发的检查项）
```

## 10. SOP-I：模型首次接入

适用场景：

```text
模型第一次拿到 00_规则。
用户要求初始化、检查规则、说明怎么用。
用户希望模型自动建立或完善引导。
```

作业顺序：

```text
读取 00_规则/00_AI工作入口.md
-> 读取 00_规则/01_规则总览.md
-> 读取 00_规则/02_全局结构与阶段规则.md
-> 读取 00_规则/11_固定SOP_全库作业流程.md
-> 读取 00_规则/19_模型首次接入与引导生成规则.md
-> 检查外层骨架和正式库入口
-> 检查给人的使用说明
-> 检查规则是否只在 00_规则
-> 检查索引/MOC/Bases 是否只作为导航或状态视图
-> 输出简短接入报告或给人的使用说明
```

禁止：

```text
不能未读规则就全库扫描。
不能把 MOC 当规则。
不能把完整 AI 规则原文输出给用户。
不能把原始记录当正式知识。
```

首次接入的具体检查和输出要求以：

```text
00_规则/19_模型首次接入与引导生成规则.md
```

为准。

## 11. 一句话判断

```text
新材料先入队。
AI 内容先候选。
用户允许再归类。
原始聊天先提炼。
提炼之后再做卡片。
正式调用只看已入库、已归类、可信内容。
```
