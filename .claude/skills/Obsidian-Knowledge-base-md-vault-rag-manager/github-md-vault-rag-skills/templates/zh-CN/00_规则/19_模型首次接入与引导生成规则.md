# 模型首次接入与引导生成规则

本文件定义模型第一次拿到 `00_规则` 后必须自动完成的接入流程。

核心目标：

```text
让模型先理解规则、检查结构、生成给人的引导，再处理内容。
```

## 1. 触发条件

出现以下任一情况，必须执行本规则：

```text
模型第一次进入本库。
用户说：初始化、第一次使用、检查规则、怎么使用、说明在哪。
用户只提供 00_规则 文件夹，要求模型接手。
发现正式库、队列区、索引或使用说明缺失。
发现规则可能散落在内容区，需要统一规则入口。
```

## 2. 必读顺序

首次接入时，先读以下文件：

```text
00_规则/00_AI工作入口.md
00_规则/01_规则总览.md
00_规则/02_全局结构与阶段规则.md
00_规则/11_固定SOP_全库作业流程.md
00_规则/19_模型首次接入与引导生成规则.md
```

然后按任务需要读取：

```text
导入/入库：03、04、05、07、08
正式库调用：06、12、13、14、18
知识库建设/检索优化：17、18
项目材料：15
每日日志：16
```

## 3. 自动检查事项

模型首次接入后，必须检查：

```text
00_规则 是否存在且为唯一规则区。
01_导入原始材料 是否存在。
02_入库处理区 是否存在。
10_正式库 是否存在。
99_垃圾区 是否存在。
10_正式库/00_正式库索引.md 是否存在。
10_正式库/01_笔记区 是否存在。
10_正式库/02_思辨区 是否存在。
10_正式库/03_项目区 是否存在。
10_正式库/04_每日日志 是否存在。
00_规则/00_给人看的使用说明.md 是否存在。
```

如果缺失骨架，按 `00_规则/11_固定SOP_全库作业流程.md` 的初始化流程创建占位结构。

## 4. 必须生成或维护的引导

首次接入时，必须确认以下引导文件存在且清楚：

```text
00_规则/00_给人看的使用说明.md
00_规则/00_AI工作入口.md
10_正式库/00_正式库索引.md
```

如果启用正式库混合检索，还要确认：

```text
10_正式库/00_检索索引/README.md
10_正式库/00_检索索引/构建报告.md
```

给人的说明必须简洁，重点说明：

```text
材料放哪里。
人工辅助模式和全自动模式怎么选。
人工审核只需要改什么标签。
结果在哪里看。
规则区和内容区的区别。
```

不要把完整 AI 规则原文输出给用户。

## 5. 首次接入输出

首次接入完成后，向用户输出简短报告：

```text
已读取哪些规则。
当前骨架是否完整。
是否生成或更新了给人的使用说明。
是否发现规则冲突或旧路径。
下一步用户应该怎么放材料或怎么发起检索。
```

如果用户只是问“怎么用”，优先输出 `00_规则/00_给人看的使用说明.md` 的简洁内容。

## 6. 规则一致性自检

首次接入或规则更新后，必须自检：

```text
规则是否只放在 00_规则。
MOC、索引、导读、Bases 是否没有被误当作规则。
00_思辨MOC 是否只作为思辨区导航。
01_思辨记录 是否只作 source 追溯或待提炼材料。
02_提炼卡片 是否作为思辨区稳定观点优先来源。
正式库调用是否遵守 06 和 18。
是否存在旧路径，如 03_每日日志。
是否存在重复、冲突、过期的规则说明。
```

发现冲突时，不直接覆盖用户内容。应先说明冲突位置，再按 `00_规则` 的集中规则修正规则文件。

## 7. 禁止事项

```text
禁止未读入口规则就直接扫描全库。
禁止把内容区 MOC 当成规则。
禁止把原始聊天当作稳定知识。
禁止输出完整规则原文给用户。
禁止创建新的分散规则文件。
禁止把检索索引当作知识正文。
```

## 8. 完成标准

首次接入完成，必须满足：

```text
模型知道先读哪些规则。
用户知道怎么使用本库。
正式库结构能被导航。
导入、入库、检索、思辨提炼都有入口规则。
后续模型可以按 SOP 继续执行，而不需要重新猜流程。
```
