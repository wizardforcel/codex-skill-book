# AI 工作入口

AI 处理这个库时，必须先读本文件，再按任务读取同文件夹内的规则文件。

## 1. 先读规则

每次必读（无论任务类型）：

```text
00_规则/00_AI工作入口.md
00_规则/01_规则总览.md
00_规则/02_全局结构与阶段规则.md
00_规则/11_固定SOP_全库作业流程.md
```

如果是第一次进入本库、只拿到规则区、初始化骨架、检查规则或生成使用引导，还必须读取：

```text
00_规则/19_模型首次接入与引导生成规则.md
```

任何模型第一次拿到 `00_规则` 时，必须先执行首次接入流程，不得直接处理内容文件。

首次完成规则检索后，必须向用户输出给人看的使用说明：

```text
00_规则/00_给人看的使用说明.md
```

触发场景：

```text
第一次进入本库
初始化骨架完成后
用户询问怎么使用、怎么开始、说明在哪
用户要求展示使用说明
```

输出要求：

```text
给用户看简洁版说明。
重点说明材料放哪里、两种工作模式、人工审核标签、结果看哪里。
不要把完整 AI 规则原文输出给用户。
```

按任务类型按需读取：

```text
导入/入库任务：
  00_规则/03_导入材料与队列规则.md
  00_规则/04_垃圾鉴别器规则.md
  00_规则/05_入库标签与人工闸门规则.md
  00_规则/07_正式库路由规则.md
  00_规则/08_入库格式模板.md

正式库调用任务：
  00_规则/06_AI调用过滤与标签检索规则.md
  00_规则/12_正式库入口规则.md
  00_规则/13_笔记区规则.md
  00_规则/14_思辨区规则.md
  00_规则/18_混合检索与向量索引规则.md

知识库建设/检索优化：
  00_规则/17_知识库建设与检索优化规则.md
  00_规则/18_混合检索与向量索引规则.md

首次接入/初始化/引导生成：
  00_规则/19_模型首次接入与引导生成规则.md

项目材料：
  00_规则/15_项目知识库规则与模板.md

每日日志：
  00_规则/16_每日日志规则与模板.md
```

## 2. 先按 SOP 分流

所有任务先按以下文件判断作业类型：

```text
00_规则/11_固定SOP_全库作业流程.md
```

不要先进入具体文件夹直接处理。先判断任务属于导入、候选、归类、思辨提炼、正式调用，还是垃圾处理。

## 3. 不默认全库扫描

AI 先判断任务类型，再只进入对应队列或文件夹。

```text
导入新材料：看 01_导入原始材料
制作候选成品：写入 02_入库处理区/02_入库候选
人工放行后归类：看 #入库/允许 或 02_入库处理区/03_待归类
垃圾处理：看 #入库/拒绝，写入 99_垃圾区
正式库调用：只看 10_正式库 中已入库、已归类、可信状态的材料
```

## 4. 你的最小操作

你只需要改候选成品的入库标签：

```text
#入库/允许
#入库/拒绝
```

AI 负责整理、鉴别、补字段、建链接、移动文件和更新归类标签。

## 5. 模板类文件

模板类文件也属于作业规则，统一放在 `00_规则`。

```text
通用入库格式：读 00_规则/08_入库格式模板.md
项目知识库：读 00_规则/15_项目知识库规则与模板.md
每日日志：读 00_规则/16_每日日志规则与模板.md
```

## 6. 建设和检索优化

新增正式条目、改模板、做批量整理、优化检索时，必须读取：

```text
00_规则/17_知识库建设与检索优化规则.md
00_规则/18_混合检索与向量索引规则.md
```

## 7. 调用硬规则

```text
没有经过垃圾鉴别的 AI 内容，不能入库。
没有 #入库/允许 的候选成品，不能正式入库。
没有 #入库/已入库 和 #归类/已归类 的内容，不能作为后续 AI 判断依据。
99_垃圾区 只能作为反面样本，不能作为知识依据。
10_正式库/02_思辨区 默认还需要按标签、frontmatter 和提炼状态区分可信度，除非具体文件已经有可信标签。
```

## 8. 区域规则读取

所有规则统一放在 `00_规则`。进入具体区域后，AI 必须先读取该区域对应的集中规则文件。

```text
进入 10_正式库 -> 先读 00_规则/12_正式库入口规则.md
进入 10_正式库/01_笔记区 -> 先读 00_规则/13_笔记区规则.md
进入 10_正式库/02_思辨区 -> 先读 00_规则/14_思辨区规则.md
```

区域规则不替代主规则，只补充本区域的导航、检索和可信度要求。

## 9. 索引和 Bases 工作台

索引、MOC 和 Bases 不是规则文件。它们保留在对应区域，用来导航和看状态；规则文件负责说明什么时候读哪个索引。

Obsidian 中优先打开这些 Bases 视图进行审核和状态查看：

```text
00_规则/09_入库审核.base
00_规则/10_全库状态.base
10_正式库/01_笔记区/00_笔记区状态.base
10_正式库/02_思辨区/00_思辨区状态.base
```

这些 `.base` 文件只读取标签和 properties，不是知识来源本身。

正式库混合检索索引位于：

```text
10_正式库/00_检索索引/
```

索引文件只用于召回候选内容，不替代规则、标签、frontmatter 和原文核验。
