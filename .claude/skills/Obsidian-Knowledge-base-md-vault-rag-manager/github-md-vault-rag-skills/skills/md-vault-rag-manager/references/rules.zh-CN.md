# 规则优先知识库规范

## 目标

把 Markdown/Obsidian 文件夹变成可被模型稳定使用的断网知识库。

核心思想：

```text
规则区决定流程和边界。
正式库提供可调用知识。
索引/MOC 只负责导航。
检索索引只负责召回候选。
最终回答必须回到原始 Markdown 证据。
```

## 推荐结构

```text
00_规则/
01_导入原始材料/
02_入库处理区/
10_正式库/
99_垃圾区/
```

正式库内部推荐：

```text
10_正式库/
  00_正式库索引.md
  00_检索索引/
  01_笔记区/
  02_思辨区/
  03_项目区/
  04_每日日志/
```

## 规则区

规则区只放流程、边界、模板、读取顺序和检索约束。

常见规则文件：

```text
00_AI工作入口.md
01_规则总览.md
02_全局结构与阶段规则.md
06_AI调用过滤与标签检索规则.md
11_固定SOP_全库作业流程.md
18_混合检索与向量索引规则.md
19_模型首次接入与引导生成规则.md
```

内容区不要再放重复规则。内容区的 `00_索引`、MOC、导读和 Bases 是导航或状态视图，不是规则。

## 首次接入

模型第一次拿到知识库时必须执行：

```text
读入口规则
-> 读规则总览
-> 读全局结构
-> 读固定 SOP
-> 检查骨架
-> 检查给人的使用说明
-> 检查规则是否散落或冲突
-> 输出简短接入报告
```

给人的说明必须简洁，只说明：

```text
材料放哪里
两种工作模式
人工审核改什么标签
结果在哪里看
规则区和内容区有什么区别
```

不要把完整 AI 规则原文输出给用户。

## 正式库调用边界

默认允许：

```text
正式库内内容
status: reviewed 或 evergreen
truth_status: source_backed 或 self_confirmed
已入库、已归类标签
summary 已填写
```

默认禁止：

```text
导入区
处理区
垃圾区
Inbox
Archive
raw
pending
rejected
unverified
原始聊天本身
```

## 思辨区约束

如果知识库有思辨区：

```text
MOC/索引：只导航。
原始记录：只追溯或待提炼。
提炼卡片：优先作为稳定观点来源。
```

不要把原始聊天直接当作稳定知识回答。

## 回答规则

回答前必须：

```text
先检索正式库。
再过滤 metadata。
再打开原始 Markdown。
最后基于证据回答。
```

如果库内证据不足，说：

```text
库内没有足够依据。
```

不要凭模型常识补完，除非用户明确要求外部知识或通用解释。
