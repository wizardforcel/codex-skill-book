# 基于资料制作PPT

严格按阶段推进。以资料证据和用户确认为最高优先级，不得跳过门禁、不得把内部判断当作用户批准、不得用看似合理的内容补足材料空缺。

## 核心原则

1. **证据优先**：所有事实、数据、成果、系统界面、案例、进度和评价结论都必须能追溯到用户资料。
2. **单页闭环**：编辑现有PPT或用户要求逐页设计时，默认一次只处理一页。当前页通过“内容核验—参考图确认—素材确认—PPT制作—渲染质检”后，才进入下一页。
3. **先参考图，后编辑PPT**：未获得当前页参考图明确确认前，不得开始该页PPT文件编辑。
4. **真实截图不生造**：系统成果、研究进展、真实场景、真实图表和应用实例不得用生图伪造。
5. **可编辑优先**：标题、正文、表格、流程、形状、箭头、标签、编号和统计框尽量使用PowerPoint原生组件重建。
6. **审计信息不上屏**：素材来源、核验结论、制作说明和待补充项保留在工作记录中，不写入正式汇报页面，除非用户明确要求。
7. **范围受控**：编辑现有PPT时，只修改用户指定页面或章节，其他页面保持不变。

## 加载执行规范

- 开始处理资料前，加载 `Presentations` 技能并遵守其叙事、实现和渲染质检要求。
- 进入页面参考图或独立插图生成阶段时，加载 `imagegen` 技能。
- 需要输出模板、证据矩阵、截图核验表、页面状态表或质检清单时，读取 [references/workflow-templates.md](references/workflow-templates.md)。

## 执行模式

### 模式A：单页严格门禁模式

适用于：

- 编辑现有PPT；
- 用户要求“一页一页设计”；
- 应用实例页、研究进展页、技术路线页等需要逐页反复确认的任务；
- 对真实性、截图来源或版式还原要求较高的任务。

每页状态为：

`页面边界已确认 → 页面证据已核验 → 页面文案已确认 → 单页参考图已确认 → 页面素材已确认 → 可编辑PPT已制作 → 单页渲染质检通过`

只有当前页达到“单页渲染质检通过”，才进入下一页。用户说“继续”只表示推进当前状态，不代表批准尚未确认的参考图、素材或PPT。

### 模式B：分批模式

仅在用户明确接受批量推进时使用。每批最多5页，每页仍需独立预览图；当前批次全部确认后才能进入下一批。用户一旦要求逐页推进，立即切换到模式A。

## 第一阶段：确认范围并检查资料

1. 确认汇报对象、用途、目标页数、目标章节和需要修改的页面范围。
2. 编辑现有PPT时，先复制原文件作为工作底稿，记录：
   - 保留页面；
   - 改写页面；
   - 新增页面；
   - 删除页面；
   - 明确禁止改动的页面。
3. 检查当前对话中用户上传或明确选定的全部资料。没有资料或资料不足时，列出缺失项并停止后续制作。
4. 阅读相关资料正文和页面图像，不以文件名、截断预览、历史记忆或常识替代实际读取。
5. 将资料分类为：
   - **内容支撑**：任务书、报告、方案、数据表、会议纪要等；
   - **参考模板**：现有PPT、页面截图、品牌规范等；
   - **真实图片素材**：系统截图、现场照片、原始图表、地图、流程图等；
   - **可生成装饰素材**：背景、概念性插图、无事实含义的装饰图；
   - **约束资料**：研究边界、验收指标、领导意见、禁止项等。
6. 出现版本冲突时，优先采用用户明确指定的底稿或最新版本；无法判断时询问用户，不得自行拼接。

不得用网络内容、记忆内容或常识补足材料中的关键成果、数字、系统界面、真实案例和研究结论，除非用户明确授权并要求区分外部资料。

## 第二阶段：压缩包与截图核验

压缩包中的文件只有完成视觉核验后，才可作为正式截图素材。

### 核验等级

- **L1 成员清单核验**：仅确认压缩包中有哪些文件、数量、名称和格式。
- **L2 解压可用核验**：文件已成功解压，可正常读取。
- **L3 视觉核验**：已逐张查看截图内容、清晰度、界面真实性和适用页面。
- **L4 正式复用核验**：已建立“截图—来源文件—页面用途—可支撑内容”的映射，可以进入PPT。

必须明确区分这些等级。仅完成RAR成员列表读取，不得表述为“截图已逐张核验”。环境无法解压时，应说明阻塞原因，请用户改传ZIP或直接上传解压后的图片，不得假装完成核验。

截图较多时，制作联系表或缩略图总览，并为每张图片记录：

- 原始文件名；
- 来源文件或压缩包；
- 截图内容；
- 清晰度；
- 可支撑的页面模块；
- 是否含敏感、无关或难以辨认信息；
- 是否可正式复用。

## 第三阶段：建立证据矩阵

在写页面文案或设计版式前，对每页拟使用的信息做证据分级：

- **A 直接支撑**：资料明确给出原文、原始数据、真实截图或真实案例记录，可以直接上屏。
- **B 结构支撑**：资料只支撑业务流程、模块名称、字段结构或定性结论，不支撑具体数值、时间、项目名或案例结果。
- **C 无支撑**：资料中不存在，或只能通过猜测、常识、生成内容得出。

使用规则：

1. A类可按原口径上屏。
2. B类只能写流程、字段、模块或定性效果，不得自行补入编号、日期、金额、长度、户数、百分比、风险等级、评分等具体值。
3. C类必须删除或向用户索取依据。
4. 页面需要占位时，使用“—”“待补充”或留白，不得制造示例数据冒充真实结果。
5. “已完成、已建立、已实现、达到、提升、下降”等结论，必须有A类证据。

### 应用实例页的命名门槛

只有同时具备真实界面和匹配的真实案例记录、工单、项目台账或结果数据时，页面才可称为“应用实例”或“案例成果”。

如果只有系统截图和业务流程依据，应改为：

- “应用流程与界面示意”；
- “业务应用展示”；
- “功能场景示意”。

不得用虚构项目名、工单编号、时间、资金、进度、影响范围、风险分值或前后对比结果来补齐案例。

## 第四阶段：大纲与逐页内容底稿

### 新建PPT

先提交大纲方案，说明：

- 汇报对象与用途；
- 建议页数和叙事主线；
- 每章目的及页面安排；
- 重点页面与拟采用资料；
- 视觉方向及参考模板来源。

大纲未确认前，不进入逐页内容。

### 编辑现有PPT

先提交页面映射，再逐页输出制作底稿。每页底稿包含：

- 页码与页面类型；
- 页面标题；
- 核心结论；
- 可直接上屏的文字；
- 信息层级与版式结构；
- 图片、图表、流程或表格需求；
- 逐项资料来源；
- A/B/C证据等级；
- 禁止项和待补充项。

正文必须严谨、确定、可上屏。删除问号式小标题，以及“可能、大概、这里介绍、材料显示”等过程性措辞。

## 第五阶段：选择页面原型

根据页面任务选择结构，不用同一种卡片模板覆盖所有页面。

### 技术路线页

推荐结构：

`问题/目标 → 关键技术突破 → 技术路线分解 → 应用输出`

要求：

- 强调技术对象、处理过程和输出关系；
- 使用流程、分层架构、算法模块、输入输出关系等可编辑图形；
- 不用系统截图堆叠替代技术路线；
- 不把计划目标写成已完成成果。

### 应用实例或业务应用页

推荐结构：

`场景问题 → 系统界面/方案结构 → 业务流程或规则 → 实际输出`

要求：

- 主视觉优先使用真实系统截图；
- 文字解释围绕截图中真实可见功能展开；
- 只有真实案例数据时才展示项目、工单、指标和成效；
- 没有真实案例时，采用定性效果，如“事件闭环可追踪、项目进度可掌握、数据更新可追溯”。

## 第六阶段：生成并确认单页参考图

1. 每一页单独生成16:9参考图，不得用拼图代替单页确认。
2. 单页严格模式下，一次只处理当前页，不得提前制作后续页面。
3. 参考图必须使用已核验文案、真实截图和确认的视觉体系。
4. 系统界面、真实图表、研究进展和实际成果不得通过生图虚构。参考图可用于版式预演，但不能产生新的界面内容、数字、图表结果或案例事实。
5. 若真实截图无法清晰放入页面，可通过扩大主图、减少截图数量、可编辑流程图、图标或留白优化，不得生成假界面替代。
6. 用户提供参考PPT时，优先继承其母版感、字体、色彩、间距、页眉页脚和视觉秩序。
7. 用户确认当前页参考图后，才进入当前页素材准备与PPT编辑。
8. 用户提出修改时，只修改受影响部分；未被指出的构图和内容保持稳定。

## 第七阶段：准备并确认页面素材

对当前页建立素材映射：

- 素材编号；
- 原始文件路径或来源文件；
- 对应参考图位置；
- 裁剪范围；
- 是否真实截图；
- 是否允许生成；
- 是否需要透明背景；
- 清晰度和复用状态。

真实截图要求：

1. 保留完整原图文件，不覆盖、不重绘、不改变数据。
2. 在PPT中优先使用Office裁剪参数控制显示范围，使原图可恢复。
3. 不把额外文字、事件卡片、指标值或标记直接烘焙到截图中，除非原始截图或资料明确包含这些内容。
4. 不将其他页面的截图强行解释为当前业务成果。
5. 需要展示多个截图时，先说明各截图分别支撑什么功能，避免语义弱、重复或无关的小图堆叠。

生成素材仅可用于背景、概念示意或装饰，不得伪装成真实系统界面、现场照片、检测结果或研究成果。

## 第八阶段：逐页还原可编辑PPT

仅在当前页参考图和素材都已确认后开始制作。

1. 以当前页最终参考图为设计依据，一比一还原构图、层级、配色和图文比例。
2. 标题、正文、表格、流程节点、箭头、线条、标签、编号、统计框和图标使用PowerPoint原生可编辑组件。
3. 不得把整张参考图作为页面背景，也不得把本应可编辑的文字烘焙进图片。
4. 简单流程和框架图先放连接线，再放节点，避免连线穿过节点或文字。
5. 图片保持正确比例，不拉伸；关键界面和数据不被裁掉。
6. 编辑原PPT时，仅替换或重做指定页面，其他页面、母版、备注和结构尽量保持不变。
7. 页面中的表格、数字和标签必须与证据矩阵一致，不得在制作阶段临时补数。
8. 制作说明、素材核验范围和待补充项不写入正式页面。

## 第九阶段：渲染、事实与交付质检

每页完成后必须先渲染为图片并全尺寸检查，当前页通过后才能进入下一页。

### 事实质检

- 所有事实、数字、项目名、工单、日期、金额、长度、百分比、风险等级和成效都有A类证据；
- B类信息未被扩写成具体案例数据；
- 没有使用C类内容；
- 页面标题与证据强度匹配；
- 真实截图与对应文字含义一致；
- 没有在截图上叠加无来源的数据或事件信息。

### 视觉质检

- 与确认参考图的构图、色彩、层级和图文比例一致；
- 无文字溢出、异常换行、重叠、裁切、连接线穿透和低清图片；
- 截图主体清楚，数量适当，不重复堆叠；
- 页面结构严谨，信息密度与留白平衡。

### 可编辑性质检

- 文字、形状、表格、流程、箭头、页码和标签均可编辑；
- 未将整页扁平化为图片；
- 原始截图仍完整保留，可恢复裁剪；
- 文件可正常打开、播放和继续编辑。

### 范围质检

- 只修改了用户指定页面或章节；
- 其他页面未被意外删除、移动或改写；
- 页面顺序、章节逻辑和母版体系保持正确。

仅在质检通过后交付可编辑 `.pptx` 和必要的页面预览。最终回复简要说明修改页数、可编辑范围、真实图片来源、未使用的无依据内容以及质检结果。

## 异常与阻塞处理

- 压缩包无法解压：说明已完成的核验等级，要求用户改传ZIP或解压后的图片；不得声称逐张核验完成。
- 只有业务流程、没有真实案例数据：制作“应用流程与界面示意”，不制作量化案例成果页。
- 真实截图清晰度不足：先尝试从原始文档、PPT或压缩包提取高清原图；仍不足时调整版式，不用生成假截图替换。
- 用户修改上游内容：退回对应状态，更新文案、参考图、素材和PPT，不沿用失效版本。
- 用户要求跳过参考图：只有用户明确授权后才能直接编辑；默认仍执行参考图门禁。
