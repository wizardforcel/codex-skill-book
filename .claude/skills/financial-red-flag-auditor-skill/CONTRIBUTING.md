# 贡献指南

感谢你愿意改进 financial-red-flag-auditor-skill。本项目把上市公司财报排雷（财务质量评分 + 红旗诊断）整理成可装入 AI Agent 的 Skill，定位始终是研究与学习工具。

> 仅供学习研究，不构成投资建议，不荐股、不估值、不给具体买卖指令、不承诺收益。本 Skill 只识别风险信号；除非已有官方监管、司法、交易所、审计或公司公告认定，绝不把"造假/虚增/资金占用/财务舞弊"作为事实结论。盈亏自负。

## 欢迎的贡献

欢迎提交以下内容：

- 新的市场适配器：A 股 / 港股 / 美股 / A+H / 中概 ADR 在会计准则、披露口径、现金流分类上的差异处理。
- 行业专属红旗规则：把某一行业的财务异常模式，转成可复现、可审计的确定性筛查规则。
- 新的问题卡 playbook：补充某一科目（应收、存货、商誉、在建工程、研发资本化、非经常损益等）的"四步验证"结构。
- 评分细则校订：让 15 维 / 100 分的扣分逻辑更可解释、更可横向比较。
- 改进的报告模板与 HTML 排版：提升长版报告的可读性与可复核性。

## PR 底线

所有贡献都必须守住以下边界：

- 保持研究口径，不荐股、不估值、不给具体买卖指令、不承诺收益。
- 明确区分确认事实、计算事实、第三方数据、解读、待核问题，不把推断包装成结论。
- 对任何具体公司只用"风险信号、强不一致、需进一步核实、疑似盈余管理"等语言；事实性指控必须有官方来源。
- 官方披露口径优先；结构化数据供应商仅作交叉校验，与公告冲突时以公告为准。
- 二次分享或改编时，请保留来源致谢与免责声明。
- 不提交任何包含账号、token、私密数据、未公开文件或未获授权材料的内容；示例请用公开官方披露或匿名化处理。

## 提交流程

1. Fork 本仓库。
2. 在你的 fork 中创建分支并修改。
3. 本地检查 Markdown 结构、链接和免责声明是否完整。
4. 提交 commit，message 使用 `feat:` / `docs:` / `fix:` 前缀。
5. 发起 Pull Request，并在说明中写清楚改动目的、影响范围和验证方式。

## 行为准则

友善沟通，对事不对人；围绕定义、证据、复核路径讨论问题。
